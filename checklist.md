# Desktop App Capability & QoL Checklist

English | [简体中文](zh-CN/checklist.md)

This checklist describes capabilities and quality-of-life behaviors that desktop GUI applications typically need beyond their core features. It is intended for review during design, implementation, and release. It applies to Windows, macOS, and Linux and is independent of any technology stack. It is not a compliance standard and does not provide scoring or certification.

For usage, product types, and a prompt for AI coding agents, see [README.md](README.md). For combined walkthrough scenarios, see [scenarios.md](scenarios.md). The sources behind the items are listed in [references.md](references.md).

## Reading path

The 229 items are not meant to be read in one pass. Follow this order, and in each pass read only what applies to the product:

1. **Untagged Baseline items in the core domains**, about 100 items. This is what nearly every desktop application needs. DATA, NETWORK, and INSTALL are tagged as whole domains; a product that holds no user data, uses no network, and has no concern with distribution can skip them, which brings the first pass down to about 70 items.
2. **Items matching the product's feature tags**, the relevant part of about 30 items. Determine the tags first with the product type table in [README.md](README.md).
3. **Conditional domains that apply**, the relevant part of 47 items. Use the "Applies to" column of the contents table.
4. **QoL items**, 89 items. They make the application more pleasant; their absence does not break it.

An AI coding agent auditing with [AUDIT.md](AUDIT.md) decides applicability itself and need not follow this order.

## How to read

**Item format**: `ID Title` · feature tags · Baseline or QoL — expected behavior. Some items include a "Common failure" line describing a typical defect.

**Baseline and QoL** help with scanning and do not indicate priority:

- **Baseline**: if missing, features break, data is lost, or the application is unusable on some systems or devices.
- **QoL**: improves efficiency and comfort.

The same item carries different weight for different users: IME support is QoL for English-only users and a prerequisite for CJK users. Each product sets its own priorities.

**Feature tags**: a tag indicates the product feature that usually makes an item apply; the item text decides whether it does. Untagged items apply to nearly all desktop applications.

| Tag | Does the product… |
| --- | --- |
| `data` | hold data that users create or organize |
| `text` | let users read or edit text, code, or logs for long periods |
| `background` | keep running after its windows are closed |
| `on-demand` | stay hidden until summoned by a hotkey and dismissed after use |
| `network` | depend on network services or accounts |
| `multi-window` | support multiple windows, tabs, or documents |
| `distribution` | behave differently depending on how it is distributed (app store, installer, portable package, package manager) |

**Domain applicability**: Conditional domains state their applicability under the heading. Skip the whole domain if it does not apply.

**Platform differences** are noted in parentheses within items. **Stack-specific implementation details** are listed by item ID in Appendix A.

**Checking items off**: `[x]` means implemented and verified in a real environment; `[ ]` means not implemented or not verified. Delete or strike through items that do not apply, with a short reason. An item deferred to a later release is a to-do, not "not applicable".

## DISPLAY · Display and layout

- [ ] **DISPLAY-01 System scaling** · Baseline — At system scaling from 100% to 200%, text is sharp, icons are not blurry, and controls are neither clipped nor overlapping.\
  Common failure: The app is developed only at 100%; at 150%, button labels are cut off and the buttons at the bottom of the settings page fall outside the visible area.
- [ ] **DISPLAY-02 Runtime display changes** · Baseline — The application adapts to changes in system scale, connected displays, resolution, or remote desktop sessions without a restart. When a restart is required, the application says so.\
  Common failure: After an external display is disconnected, the window stays on the removed display.
- [ ] **DISPLAY-03 Mixed DPI** · Baseline — When a window moves between displays with different scale factors, layout, menus, popup positions, and click targets remain correct.\
  Common failure: On a 4K display, clicks land half a button away from the pointer.
- [ ] **DISPLAY-04 Window size adaptation** · Baseline — At the declared minimum window size and at half-screen snap size, primary actions remain reachable and overflowing content can be scrolled or collapsed. A minimum size that is too large prevents the window from fitting into Windows snap layouts. A larger window shows more content, and body text, forms, and settings pages have a maximum width.\
  Common failure: A fixed minimum width of 1280 pixels prevents side-by-side use with a browser on a laptop.
- [ ] **DISPLAY-05 Content zoom and UI scaling** · QoL — Ctrl/Cmd + scroll wheel and Ctrl/Cmd + plus or minus zoom the content; Ctrl/Cmd + 0 resets it. Content zoom is independent of UI scaling, so sidebars and buttons do not grow with the content. UI scaling can be set separately inside the application. When either zoom departs from its default, its current ratio is shown and can be reset in one action. For temporary zoom and the saved default, see SETTINGS-05.
- [ ] **DISPLAY-06 Text enlargement and reflow** · Baseline — When the system or application enlarges text, or when long paths, long file names, or longer translations appear, the layout stays intact and buttons remain within reach. Names, paths, and labels shortened for lack of space can be viewed in full.\
  Common failure: German strings run about 40% longer than English, and every toggle label on the settings page is truncated.
- [ ] **DISPLAY-07 Consistent secondary UI** · Baseline — Menus, tooltips, dialogs, drag previews, and floating panels use the scale factor of the display they appear on, and key content stays readable and operable. System-managed menus and dialogs are handled within the limits of the system. For theme consistency, see APPEARANCE-01.
- [ ] **DISPLAY-08 No flashing, no jumping, stable targets** · QoL — In dark mode, startup does not flash a white screen. Asynchronously loaded content has reserved placeholder height. Automatic sorting, inserted items, and background refreshes do not change the target under the pointer or interrupt a rename or edit in progress (protection of the input is covered by DATA-03). When content above loads, expands, or reflows because a pane changed width, the content the user is reading stays in place.\
  Common failure: A list refresh shifts items down one row, and the user clicks "Delete" on the adjacent item.
- [ ] **DISPLAY-09 Scroll stability and high refresh rates** · QoL — Scrolling is stable without dropped frames on 60 Hz displays. On displays of 120 Hz and above, scrolling and animation are not locked to a lower frame rate. For throttling while hidden, see TASK-08.
- [ ] **DISPLAY-10 Color management and HDR** · Baseline — Products centered on images, video, or color accuracy handle the color spaces of content and display correctly and document the supported range. Unsupported HDR content or color gamuts are presented or converted in an understandable way. For UI themes, see APPEARANCE-01; for editor and canvas color schemes, see APPEARANCE-02.\
  Common failure: Images exported on a wide-gamut display show a color shift on other devices.

## TYPO · Fonts and text

- [ ] **TYPO-01 System fonts and script fallback** · Baseline — The default font is legible. Missing glyphs fall back appropriately. CJK characters, emoji, and common symbols render correctly. In Chinese locales, Han characters such as 骨, 直, and 门 use Chinese glyph forms. Mixed-language content selects glyphs by the language of each run, not only by the UI language.\
  Common failure: Chinese text renders as boxes on Linux; emoji render as blank space.
- [ ] **TYPO-02 Adjustable content font and size** `text` · QoL — Editing, reading, and log areas each have their own font and size settings (monospace by default for code), with a preview and a one-click reset. After a font change, the caret, selection, and column alignment remain accurate.
- [ ] **TYPO-03 Adjustable UI font** `text` · QoL — Products used for long sessions allow changing the UI font. After a change, menus, buttons, and settings pages are not clipped, and the settings distinguish the system default from a user choice. If inheriting the system font is sufficient, this option is unnecessary.
- [ ] **TYPO-04 Typography settings** `text` · QoL — Line height, letter spacing, and ligatures can be adjusted as needed. In code contexts, ligatures can be turned off and easily confused characters (0/O, 1/l/I) are distinguishable.
- [ ] **TYPO-05 Fallback for missing fonts** · Baseline — After a user-selected font is uninstalled, the application starts and renders normally, and the settings indicate that a fallback is in use.\
  Common failure: The application crashes on startup when the selected font is missing, and the user has to delete the configuration file manually.
- [ ] **TYPO-06 Selectable and copyable text** · Baseline — Paths, error details, logs, status bar values, and version numbers can be selected or copied in one action. Copy confirmation is lightweight, such as the button briefly showing ✓.\
  Common failure: Text in an error dialog cannot be selected, so users report problems with screenshots.
- [ ] **TYPO-07 Invisible characters can be shown** `text` · QoL — Products that edit text can show markers for spaces, tabs, line endings, and control characters, either everywhere or only within the selection. Markers affect display only and do not change the content.\
  Common failure: Two trailing spaces on a Markdown line and mixed tab indentation change the result, and nothing in the UI shows where they are.

## A11Y · Accessibility

- [ ] **A11Y-01 Core workflows by keyboard** · Baseline — Primary workflows can be completed without a mouse, with no keyboard traps where focus can enter but not leave. When Tab inserts indentation in an editor, a standard way to move focus out of the editor is available. In a window divided into regions such as a sidebar, an editor, and a panel, F6 and Shift + F6 move focus between the main regions (macOS follows its own conventions). Collapsed regions are consistently either skipped or expanded.
- [ ] **A11Y-02 Visible focus, logical order, focus return** · Baseline — The focus location is visible (the focus ring may appear only during keyboard use). Tab order matches visual order. After a dialog or menu closes, focus returns to the control that opened it. When a dialog or new window opens, focus lands on the first place that needs action. When the object that held focus is deleted, focus moves to an adjacent item or its container rather than the start of the window. When focus moves by keyboard, the focused item scrolls fully into view. Autocomplete, formatting, and validation do not move focus away while the user may still be editing the current field.\
  Common failure: Custom-drawn controls have no focus ring, and keyboard users cannot tell where they are.
- [ ] **A11Y-03 Assistive technology semantics** · Baseline — Controls expose a name, role, and state. Icon-only buttons have a readable description of their purpose. For controls with visible labels, the accessible name matches the visible text, so voice control users can operate them by the words on screen. Custom trees, tables, canvases, and editors provide navigation or equivalent actions, and items in virtualized lists remain locatable. Custom lists, trees, tables, toolbars, and tab bars each take a single Tab stop and use arrow keys inside; Home and End go to the first and last item, and typing the start of a name jumps to a match. In trees, Right Arrow expands and Left Arrow collapses or moves to the parent. Re-entering returns to the selected item. Documents exported for other readers keep headings, reading order, text language, links, and image alternative text as far as the target format allows. Export options that convert content to images or drop this structure state this before they are chosen.\
  Common failure: A screen reader announces the whole toolbar as "button, button, button".
- [ ] **A11Y-04 Announced state changes** · Baseline — Save failures, task completion, and validation errors are conveyed to assistive technologies without repeated interruptions. Streaming output is not announced character by character, and the finished content can be navigated and copied reliably.
- [ ] **A11Y-05 Contrast and high contrast mode** · Baseline — Text, focus indicators, and key controls meet the contrast standard the product has chosen. System high contrast mode is respected.
- [ ] **A11Y-06 Not relying on color alone** · Baseline — Success, failure, selection, differences, and chart categories are also conveyed by text, shape, or icon.
- [ ] **A11Y-07 Respecting reduced motion** · QoL — When the system's reduced motion setting is on, large movement and zoom transitions are turned off. No information is conveyed by animation alone. Non-essential autoplay, carousels, and continuously moving content can be paused.
- [ ] **A11Y-08 Pointer effort** · Baseline — Click targets are large enough. Drag operations (resizing panels, reordering, moving objects, canvas selection) have keyboard, menu, or property panel alternatives. No fast, precise, or repetitive movements are required. Timed interactions can be extended. Action buttons and necessary descriptions do not appear only on hover; keyboard focus and touch reach them as well. Hover content stays open while the pointer moves into it. Hover content that covers other content can be dismissed without moving the pointer or focus, for example with Esc. Where precise values or distant dates are needed, sliders and date pickers also accept direct input. Ordinary buttons activate when the pointer is released. Moving the pointer off the button before release cancels the action. Actions that must respond on press, such as drawing or playing an instrument, are exempt.
- [ ] **A11Y-09 Multisensory equivalents** · Baseline — Necessary audio, video, and visual cues have captions, transcripts, or text alternatives as needed. Information conveyed only by sound has another sensory path.
- [ ] **A11Y-10 Photosensitivity and flashing** · Baseline — The application's own prompts and animations do not flash large areas rapidly. Non-essential continuous blinking can be stopped.\
  Common failure: On connection failure, the whole window flashes red and white at high speed, and keeps doing so with reduced motion enabled.

## INPUT · Keyboard, mouse, IME, and clipboard

- [ ] **INPUT-01 Platform shortcuts and keyboard layouts** · Baseline — Copy, paste, undo, save, find, and close follow the conventions of the target platform, and shortcut hints show the actual platform keys (⌘ on macOS). On macOS, ⌘W closes the window, ⌘Q quits, and ⌘H hides, each separately. On non-US keyboard layouts, shortcuts are displayed for the current layout, and punctuation-based shortcuts are tested. When the current keyboard layout cannot be detected, it can be set by hand. Characters typed with AltGr do not trigger Ctrl + Alt shortcuts (Windows). On macOS, the menu bar is complete: every command can be found in a menu, unavailable items are disabled rather than hidden, single-window applications still have a Window menu, and Quit goes through the application's own close flow.
- [ ] **INPUT-02 Dialog conventions** · Baseline — Esc cancels or closes, Enter activates the default button, and Tab moves between controls. The default button of a destructive action is not "Delete". When menus, suggestion lists, and dialogs are nested, Esc and clicking outside close only the topmost layer. While a suggestion list is open, Enter accepts the suggestion instead of submitting the form. After all layers close, the window is clickable and scrollable again. Cancelling an input box partway through a flow ends the whole operation instead of continuing with empty values.
- [ ] **INPUT-03 Discoverable shortcuts** · QoL — Shortcuts appear next to menu items and in tooltips. One place lists all shortcuts.
- [ ] **INPUT-04 Customizable shortcuts** · QoL — Action-heavy products allow changing and resetting shortcuts and report conflicts. The key binding UI shows the keys actually detected. Default shortcuts avoid combinations reserved by the system and those used by common input methods. Shortcut scheme presets are offered, including schemes that match comparable products, and a key can be looked up to find its action. Actions that depend on the numeric keypad, the middle mouse button, or a particular modifier have an alternative when that key is absent.
- [ ] **INPUT-05 Command palette** · QoL — Products with many commands or settings provide an entry point such as Ctrl/Cmd + K or Ctrl/Cmd + Shift + P that fuzzy-searches and directly runs commands, pages, and settings. Basic commands also remain in the menus. Commands that are currently unavailable remain in search results with the reason, in the same way that unavailable menu items are disabled rather than hidden. Matching names across languages is covered in LOCALE-05.
- [ ] **INPUT-06 IME composition** · Baseline — Shortcuts and submit actions do not fire during IME composition. Pressing Enter to confirm a candidate does not submit the content, and the candidate window follows the insertion point. When an IME is active but not composing, shortcuts such as Ctrl/Cmd + S and Z work normally, and composition handling does not block Ctrl/Cmd combinations or Esc. Dead-key input (accented characters in European layouts) is likewise unaffected by key interception. Text committed by an IME triggers filtering, first-item highlighting, and Enter selection the same way typed text does. Custom-drawn and embedded text areas use the platform text input interfaces, so the system emoji panel, dictation, handwriting input, and system writing tools can insert and replace text in them.\
  Common failure: Pressing Enter to confirm a candidate in a chat input sends the message.
- [ ] **INPUT-07 Standard text editing behavior** · Baseline — Caret movement, Shift-extended selection, double-click to select a word, triple-click to select a line, Ctrl/Alt + Backspace to delete a word, and Home/End follow platform conventions. Undo granularity is reasonable. Caret movement, deletion, selection, and length limits operate on user-perceived characters, so emoji sequences and combining characters are never split. Autocorrect, smart quotes, and automatic substitutions can be undone and turned off, and do not rewrite code, paths, or credentials. For a link in an editing area, a single click only places the caret; Ctrl/Cmd + click or an explicit open command follows it. In read-only views, a single click can open it.
- [ ] **INPUT-08 Context menus** · QoL — Objects offer relevant actions in a context menu, which can also be opened from the keyboard (Shift + F10 or the Menu key).
- [ ] **INPUT-09 Drag in** · Baseline — Supported files and objects are accepted, with a highlighted drop target on hover. Dropping unsupported content produces feedback. Every task also has a non-drag entry point. Existing file paths, in-memory images, virtual files, and deferred (promised) files are handled as the product requires, and cancelled drags produce feedback. When a drop immediately sends content to other people or uploads it to a shared location and cannot be undone, the drop is confirmed first. For the drag itself, see INPUT-21.\
  Common failure: Dragging a file from the file manager works, but dragging an attachment from an email client does nothing.
- [ ] **INPUT-10 Clipboard formats and lifetime** · QoL — The clipboard carries consistent formats appropriate to the content (plain text, rich text, image, file objects), and the format received by target applications is tested. Editing areas offer paste as plain text with the platform's usual shortcut (commonly Ctrl + Shift + V on Windows and Linux, ⌥⇧⌘V on macOS). When the clipboard holds several representations at once (vector and bitmap, local file and online original), the default choice is stated and can be changed to asking each time; options that fetch the original over the network are off by default and labeled. Ordinary copied content can still be pasted after the source window closes or the application quits. In terminals, command consoles, and other places where pasted text can run immediately, a paste that contains multiple lines or ends with a line break can be reviewed and canceled before it runs. Sensitive content follows the retention period described in PRIVACY-07.
- [ ] **INPUT-11 Multi-selection and batch actions** · QoL — Lists support Shift/Ctrl (⌘ on macOS) multi-selection and Select All, and indicate whether Select All covers the current page, the filtered results, or all data. The impact of a batch action can be previewed, and replace-type actions show the before and after. After a partial failure, successes and failures are listed, and only the failed items can be retried. Selections kept across pages or filters show a total that includes items not currently visible and can be cleared at once. In batch editing, properties with differing values show a mixed state, and only the properties the user changed are applied to all.
- [ ] **INPUT-12 Touchpad, touchscreen, pen, and extra mouse buttons** · QoL — Touchpad smooth scrolling, pinch zoom, and inertial scrolling work. When the pointer is over a horizontal tab strip or a wide table, the scroll wheel scrolls horizontally. Touch targets are large enough. Mouse side buttons go back and forward; the middle button closes or opens tabs. The system's scroll direction, scroll speed, and double-click interval are respected, and the scroll wheel does not change the value of a number field or dropdown the pointer happens to pass over. Products that depend on pen input, such as drawing or annotation tools, check pressure, pen buttons, and switching between pen and touch, and provide diagnostics when a device is recognized only as a mouse. When pressure is missing or the pen tip and pointer are misaligned across multiple displays, the pen input interface can be switched and the mapped area calibrated.\
  Common failure: Two-finger touchpad scrolling on Windows jumps in fixed steps.
- [ ] **INPUT-13 Drag out** · QoL — Images, generated files, and export items in the application can be dragged directly to the desktop, a file manager, or a chat window.
- [ ] **INPUT-14 Undo over confirmation** · QoL — Frequent, reversible actions (archive, remove, close tab, switch profile) take effect immediately and offer Ctrl/Cmd + Z or a brief "Undo" bar. Confirmation dialogs are reserved for irreversible actions. Actions that end several pieces of work at once, such as Quit and "Close all", can be set to run only after confirmation or while a shortcut is held, optionally only when triggered from the keyboard; with unsaved changes, that confirmation and the DATA-03 prompt are merged into one. For undo scope and history, see DATA-04. When an undo prompt replaces a confirmation, the irreversible part, such as permanent deletion or sending, runs only after the prompt is gone.\
  Common failure: Every deletion asks for confirmation, users learn to click "OK" by habit, and they confirm an accidental deletion the same way.
- [ ] **INPUT-15 Protecting input in modals and drawers** · QoL — After the user has entered content in a dialog or side drawer, an accidental click on the backdrop or press of Esc prompts for confirmation or keeps a draft.
- [ ] **INPUT-16 Smart paste** `text` · QoL — Pasting an image from the clipboard inserts it as an inline image or attachment. Pasting a URL over selected text creates a link. Automatic conversions can be undone.
- [ ] **INPUT-17 Separating browsing from activation** · QoL — Moving through lists, tabs, and previews with arrow keys does not trigger irreversible actions or actions with external side effects. When a preview loads with the selection, it does not block further browsing. When loading has noticeable latency or data cost, activation requires Enter or Space. While browsing in quick succession, items open in a single preview slot and become permanent tabs only once edited or explicitly kept. Leaving browsing or a quick search with Esc returns to the previous selection and reading position.
- [ ] **INPUT-18 Input constraints and inline correction** · Baseline — Forms state required fields and format requirements. Validation errors point to the specific field and say how to fix it. Correcting one field keeps the other valid input. Format notes and examples remain visible after typing starts rather than living only in placeholders. Information already given earlier in a flow can be carried into later steps, and going back a step and forward again keeps what was entered. In products built around sizes, coordinates, or durations, numeric fields accept simple arithmetic and units, such as `10cm + 3in`. Input that cannot be evaluated is flagged in the field, and the previous value is kept.\
  Common failure: After filling in ten fields, the user gets only "Invalid parameters", and closing the dialog clears the whole form.
- [ ] **INPUT-19 Assisted authentication** · Baseline — Sign-in and verification flows accept autofill from credential managers and pasting of complete passwords and verification codes. Segmented code fields accept a pasted code as a whole.\
  Common failure: A six-digit code is split into six boxes, and pasting fills only the first one, so the user has to type it digit by digit.
- [ ] **INPUT-20 Spell checking and dictionaries** `text` · QoL — Areas for natural-language writing offer spell checking for the selected language. It can be turned off, the dictionary can be changed, and personal words can be managed. The spell-checking language is set independently of the UI language. Products used for writing in several languages can enable multiple dictionaries at once or set the language for a document, paragraph, or selection.\
  Common failure: Typing in another language under an English UI marks every word as misspelled, and the settings allow neither changing the language nor turning it off.
- [ ] **INPUT-21 Dragging within the application** · Baseline — When dragging an object, a splitter, or a column edge, Esc cancels and returns to the state before the drag. The drag ends when the pointer is released outside the window or over an embedded web view, when the user switches to another application, or when the system cancels a touch, and that release does not also click the control underneath. Dragging to the edge of a scrollable area scrolls it. Before the drop, it is clear whether the result is a move or a copy, and the platform's modifier keys switch between them. After the drop, the result stays selected. Drag-to-move for selected text, tabs, and panels can be turned off or changed to require a held modifier key.\
  Common failure: After the mouse button is released over an embedded web preview, the panel keeps resizing with the pointer and the rest of the window ignores clicks.
- [ ] **INPUT-22 Configurable send key in submit-style inputs** · QoL — In chat, comment, and conversation inputs where several lines are entered before submitting, Enter can be switched between sending and inserting a line break, and another combination (Shift + Enter or Ctrl/Cmd + Enter) does the opposite. The default follows platform and product-type conventions. This setting is not reverted by "Reset all shortcuts", or the reset states whether it is included. Enter during IME composition is covered by INPUT-06.\
  Common failure: After switching from another chat application, the user presses Enter out of habit to start a new line, and half a sentence is sent.

## WINDOW · Windows

- [ ] **WINDOW-01 Position and size restoration** · Baseline — Window size, state, and position are remembered and restored in the way the platform allows. After a display is removed or the scale changes, the window returns to a visible area. On platforms where the window manager controls placement, such as Wayland, the application does not set absolute coordinates and relies on the system to keep the window accessible. The default window size on first launch fits the current display.
- [ ] **WINDOW-02 Window state and system window management** · Baseline — Maximized and full-screen states are restored according to platform rules, and the window position is reasonable after leaving full screen. Snap layouts, virtual desktops, macOS full-screen spaces, and Linux tiling window managers are supported. Custom title bars keep double-click to maximize, edge resizing, and the Windows 11 snap layout flyout on hovering the maximize button.\
  Common failure: After switching to a custom title bar, the Windows 11 snap layout flyout no longer appears.
- [ ] **WINDOW-03 Clear close, minimize, and quit behavior** `background` · Baseline — The outcome of closing the current window, closing the last window, background tasks, and quitting is predictable and follows platform conventions: on macOS, the application usually keeps running after its windows close; on Windows and Linux, it usually quits. A macOS application may also choose to quit when the last window closes. Products that keep running after the window closes show a notice the first time and offer a "Quit when window closes" option. Guarding Quit against accidental triggering is covered by INPUT-14. After an explicit quit, helper processes and capture tasks started by the application end as well (see COMPONENT-03).\
  Common failure: The user believes the application has closed while it keeps running in the background; on the next launch, no window appears because an instance is already running.
- [ ] **WINDOW-04 Multi-window and multi-instance rules** `multi-window` · Baseline — Single-instance or multi-instance behavior is chosen to fit the product (separate projects or identities may need separate instances). Data, focus, and open behavior between windows or instances follow defined rules, and configurations do not overwrite each other. When a stable and a beta release, or installations in different locations, coexist, instance detection, configuration, data, and external-open routing follow equally clear rules. Closing one main window does not close other main windows, and a document-level dialog blocks only its own document.
- [ ] **WINDOW-05 Routing on relaunch and external open** · Baseline — Clicking the application icon again or opening a file from outside goes to the correct window and locates the target object. Requests to open a file, a deep link, or command-line arguments received before the application has started are carried out once loading finishes and are not overridden by restoring the previous session. Under fast user switching or concurrent sessions, single-instance locks, local ports, and lock files are isolated per user session, so users neither block each other nor see each other's content. In products that hold a list or queue, opening or dropping objects from outside can be set to replace the current content, append to the list, or open another window, and replacing the current list is not the default. When the single-instance channel or local port cannot be created, or the previous instance has not finished quitting, relaunching still shows a window, states the reason, and offers a way to end the leftover process. See Appendix A for implementation.\
  Common failure: Opening a file externally starts a second instance, and the two instances overwrite each other's configuration.
- [ ] **WINDOW-06 Workspace and view context restoration** `multi-window` `data` · QoL — Tabs, layout, and context are restored. After switching tabs, returning from a detail view to a list, or restarting, scroll position, search terms, filters, sort order, column widths and order, selection, tree expansion, and caret position are preserved. If an object no longer exists, the view moves to a nearby position. Missing files do not block startup. Viewer-type products decide what to restore and when based on the task and privacy expectations. Before restoring undo history, caret, and folding, the application checks that the file was not modified externally while closed; if it was, that state is not restored. Products that jump between many objects offer Back and Forward along the visited path. Restoring the previous session at startup can be turned off. When restoration crashes or hangs, the application can start without restoring the session (see HELP-07), and the session record is kept.
- [ ] **WINDOW-07 Window title with context** · QoL — The title includes the document name or current object and marks unsaved changes (a dot in the close button on macOS, typically `*` or `●` on other platforms). Multiple windows are distinguishable in Alt-Tab on Windows and in the Window menu and Mission Control on macOS. Unnamed objects use the beginning of their content as the title, so several unnamed objects can be told apart.
- [ ] **WINDOW-08 No focus stealing** · QoL — Completed background tasks, available updates, and failed reconnects do not bring the window to the front, and in particular do not pop up a window that captures Enter while the user is typing in another application. No popups appear while another application is in full screen or presenting. System notifications or taskbar/Dock status are used instead. When the user appends objects to a list from outside, whether the window comes to the front is configurable.
- [ ] **WINDOW-09 Always on top** `on-demand` · QoL — For side-by-side reading, floating tools, and mini modes, the window can be pinned on top in one action, with a visible indicator, and unpinned.
- [ ] **WINDOW-10 Quick summon and focus return** `on-demand` · QoL — The window appears immediately when the hotkey is pressed and closes on Esc. After it closes, focus returns to the application the user was using before. Repeated summoning and dismissal do not accumulate processes or memory. When selected content is sent back to the previous application and the target does not accept simulated keystrokes (remote desktop, virtual machines, some custom controls) or no insertion point can be found, the content remains on the clipboard for manual pasting, and the hotkey's modifier keys do not linger in the target application. For where the window appears and how it reopens, see WINDOW-13. For alternatives when the hotkey fails, see SYSTEM-11.\
  Common failure: After a translation popup closes, focus stays on the desktop, and the user has to click the editor again to continue typing.
- [ ] **WINDOW-11 Closing the last tab** `multi-window` · QoL — Pressing Ctrl/Cmd + W repeatedly down to the last tab leaves an empty workspace or welcome page (configurable). One extra press does not quit the application.
- [ ] **WINDOW-12 Placement and stacking of owned windows** · Baseline — Owned windows such as dialogs, settings, and detail windows open on the display of the window they belong to and stay above it. Switching back to or restoring the owner window brings them along. When the owner closes, they close with it or are kept according to a defined rule.\
  Common failure: A modal dialog ends up behind the main window, which ignores clicks, so the user assumes the application has hung.
- [ ] **WINDOW-13 Where an on-demand window appears and how it reopens** `on-demand` · QoL — The window appears on the current virtual desktop. Which display it appears on (the one with the pointer, the one with the active window, or the primary display) and its position are configurable and can be reset. Its appearance does not interrupt a rename or IME composition in progress in the application that was in front. It hides automatically on losing focus, stays after being pinned (see WINDOW-09), and hides when the summon hotkey is pressed again. On the next summon, the previous input and navigation level are kept or reset by a configurable rule, such as returning to the initial state after being hidden for a period of time.\
  Common failure: A launcher always appears on the primary display while the user is working on a secondary display, and every summon means turning to look for it.

An accidental reload does not lose page state. External links open in the system browser, and the main window does not navigate to external pages. Production builds do not show the developer context menu. Reload and print remain available when they are product features. See Appendix A for implementation details.

## SETTINGS · Settings

- [ ] **SETTINGS-01 Discoverable, task-oriented, usable defaults** · Baseline — Settings are in the conventional location (Settings… in the application menu with ⌘, on macOS; a gear icon or menu item on other platforms). Settings are grouped by user task, not by code module, and each has a one-sentence description. The default configuration is enough to complete the first meaningful task. With many settings, common ones are shown by default, and advanced parameters and developer options are kept in an "Advanced" group or revealed by one switch; changing what is shown does not change values already set.
- [ ] **SETTINGS-02 Searchable settings** · QoL — When settings span more than one screen, search is available and covers common synonyms (for example, "font size", "DPI", and "proxy" each find the relevant setting). Settings that differ from their defaults can be filtered out and restored one by one. Search also covers descriptions, option values, and settings on subpages and in dialogs. A match inside a dialog is marked on the control that opens the dialog. Advanced settings hidden by default appear in results with a label, or the results indicate that advanced settings also match. Each setting has an ID that stays the same across UI languages and versions and can be viewed, copied, and searched for. Matching names across languages is covered in LOCALE-05.
- [ ] **SETTINGS-03 Clear timing of effect** · Baseline — Toggles that apply immediately do not have a redundant Save button. Settings that require confirmation or a restart are clearly marked. A toggle shows its actual state: "taking effect" while an asynchronous change is in progress, and "could not take effect" when enabling fails.
- [ ] **SETTINGS-04 Reliable persistence, tolerant of manual edits** · Baseline — Settings are written atomically to a location appropriate to the platform and distribution method (`%APPDATA%` or the registry on Windows, `~/Library/Application Support` or a plist on macOS, `$XDG_CONFIG_HOME` on Linux). When a hand-editable text configuration is offered and contains a syntax error, startup reports the line and column and runs with defaults, leaving the original file unchanged.\
  Common failure: A power loss leaves the configuration file half-written, and the next launch crashes.
- [ ] **SETTINGS-05 Clear scope** · QoL — When settings exist at multiple levels such as global, workspace, project, account, or file type, the override relationships are visible. Zoom, volume, and speed adjusted temporarily while viewing or playing do not overwrite the saved default; whether they carry over to the next object is configurable.
- [ ] **SETTINGS-06 Exportable, editable, syncable configuration** · QoL — Products with migration needs provide a configuration export or backup. Readable text configuration makes manual editing and version control possible. The settings page offers buttons to open the configuration, log, and data folders. Exports exclude secrets by default. With cross-device sync, machine-specific values (local paths, device selections, display layout), platform-specific shortcuts, and credentials are not overwritten by sync. Machine-specific settings saved inside a document or project, such as the printer or view position, do not take effect by default when opened on another computer or by another user.
- [ ] **SETTINGS-07 Reset by category** · Baseline — The scope of a reset is stated beforehand. Resetting preferences does not delete user data. Before a reset or a configuration clear, the previous copy is kept automatically so the change can be rolled back. "Don't show again" is offered only for routine prompts; confirmations involving risk always appear. Hidden prompts can be restored in one step from settings.
- [ ] **SETTINGS-08 Migration on upgrade** · Baseline — Valid settings are preserved after an upgrade. Obsolete options come with an explanation and an alternative. When a new version changes how older files are interpreted (units, DPI), opening an old file explains the difference first and offers a conversion instead of silently changing dimensions. When a new major version keeps a separate configuration, its first launch can import settings and extensions from the previous version, and user-installed extensions, templates, and scripts survive the upgrade.

## LOCALE · Language and region

- [ ] **LOCALE-01 UI language** · Baseline — The UI follows the system language by default and can be switched manually without reinstalling. Missing translations fall back to English instead of showing blanks or string keys.
- [ ] **LOCALE-02 Complete translations** · Baseline — Key workflows, error messages, and settings have no untranslated strings and no concatenated sentences that break grammar in other languages. Plurals, zero quantities, and counting words follow the rules of the target language.
- [ ] **LOCALE-03 Dates, numbers, units, and currency** · Baseline — Formats follow the selected region. The first day of the week is correct. Regional format is separate from UI language: date and time formats follow the system's regional format by default and can be changed separately inside the application. The default paper size likewise follows the region. The meaning of input and export formats is unambiguous. Numeric input is parsed with the region's decimal and grouping separators, so `1,5` is never silently read as `15`. Products that support regional calendar eras (Japanese era names, the Minguo calendar, the Buddhist calendar) do not hard-code era conversion, and a new era displays without a new release.
- [ ] **LOCALE-04 Time zones** · Baseline — Products that deal with time distinguish local time, fixed time zones, and times across regions. Local times that repeat or do not exist because of daylight saving transitions are handled explicitly. Time zone rules (daylight saving start and end, zone offsets) follow the system or can be updated independently instead of being fixed in a database bundled with the program. After a region changes its rules, the times the application shows match the system clock without waiting for a new release.\
  Common failure: After a region switches to permanent daylight saving time, the system clock is correct, but every time shown in the application is off by one hour.
- [ ] **LOCALE-05 Multilingual text handling** · QoL — Line breaking, word segmentation, sorting, and case conversion are correct for the target languages. Numbers in file names and similar lists sort by numeric value (`Chapter 2` before `Chapter 10`), consistent with the system file manager. Search tolerates the writing variants of each language, such as pinyin initials and Traditional/Simplified Chinese, Japanese kana, Latin diacritics, full-width/half-width characters, and different Unicode encodings of the same character, so a name copied from another system is still found. In a localized UI, built-in commands, settings, and pages can be found by both their localized names and their original English names, and results show the English name. The product decides which variants to support.
- [ ] **LOCALE-06 Right-to-left scripts** · Baseline — Products that support Arabic or Hebrew mirror the layout, orient icons correctly, and render bidirectional text correctly. Bidirectional text in file names and identifiers does not let direction control characters disguise the real name or extension.

## DATA · Data protection, saving, and recovery `data`

- [ ] **DATA-01 Visible save state** · Baseline — Saved, unsaved, saving, and save failed are distinguishable. A new document that was never edited, or a document only reformatted automatically by the program, is not marked unsaved and does not prompt on close.
- [ ] **DATA-02 Autosave and crash recovery** · Baseline — Unpersisted edits are saved automatically according to a defined policy. After an abnormal exit, the next launch offers recovery and states the time range that may have been lost. When recovered content conflicts with a file that was updated externally, both versions are kept for the user to preview and choose. Recovered content carries its encoding, line endings, and target path. When autosave writes back to the original file, a copy can be created and opened for editing before changes begin, or the file can be opened as a template or read-only. The file that receives the current edits and autosaves is clearly indicated.\
  Common failure: Autosave is enabled, but after a crash the recovered version is three hours old and no notice is shown.
- [ ] **DATA-03 Protecting unsaved changes** · Baseline — Unsaved changes are handled before closing, quitting, switching objects, system shutdown, or an application update. Background refreshes, automatic sorting, and sync never discard a rename or edit in progress. When quitting or closing several objects at once, the unsaved objects are listed in one dialog, where all can be saved, all discarded, or each handled individually.
- [ ] **DATA-04 Undo and redo targets** · Baseline — The scope of undoable actions is clear, and undo remains available after saving. With multiple editors or windows, it is clear which object Ctrl/Cmd + Z affects, and a focus change does not cause edits in another place. Undo and redo entries name the action they apply to; when the result is outside the visible area, the view moves to it. Reverting a batch of changes from an import, a bulk replace, or automatic generation does not also revert edits the user made by hand in the meantime.
- [ ] **DATA-05 Version history and backup** · QoL — Where needed, version history or backups can be viewed and restored, and the retention period is stated. Sync is not backup: incorrect content is synced to every device just the same. A backup is a consistent copy that restores data and attachments into an empty directory. Databases in use are exported through a backup interface; see Appendix A.
- [ ] **DATA-06 Safe writes** · Baseline — A failed or interrupted write leaves the original file intact. In-memory content is preserved, and the user can retry or save elsewhere. After a replace-save, the original file's permissions and attributes are unchanged, so a private file does not become readable by other users; a symbolic link is saved through to its target, and a file with multiple hard links does not have its links broken without notice. When only part of the content is loaded because of size or count limits, this is clearly marked, and saving never overwrites the original with the partial content. "Delete source after completion" and in-place replacement verify that the output is complete before deleting the source; when the task fails or verification fails, the source is left untouched and the reason is shown. See Appendix A for implementation.\
  Common failure: When the disk is full, saving truncates the original file to 0 bytes.
- [ ] **DATA-07 External changes and conflicts** · Baseline — When another program modifies, moves, or deletes a file, or a remote copy is changed concurrently: without unsaved changes, the file reloads automatically; with a conflict, the user is notified and both versions are kept. File watching keeps working after another program saves by writing a temporary file and replacing the original, after a rename, and after storage disconnects and reconnects. When events are missed, a manual refresh or rescan is available. Conflict handling is checked per data type; text, attachments, canvases, and configuration may each need different handling. A draft belongs to its own object, so text written in a notification quick reply does not appear in another conversation, and cloud draft sync does not overwrite what is being typed locally. In configuration or data files shared with other programs, the application changes only its own entries and preserves unknown fields and comments; the UI states which settings are shared.
- [ ] **DATA-08 Import, export, and data portability** · Baseline — Export formats suitable for long-term retention and migration are available, preferring common or publicly documented formats. Batch export is supported. Exports cover as much user data as possible, and content that cannot be exported, external dependencies, and lossy parts are disclosed in advance. "Save full project" and "Export to interchange format" can coexist, with the UI indicating which one preserves full state. Exported results have been opened at least once in a clean environment. When importing objects that carry tags, categories, or linked resources, the user chooses how that supplementary information merges into the local system (import all, keep only what exists locally, do not import, ask each time), and the default can be set back to "ask each time" in settings. When automatic type detection on import could change the data (dropping leading zeros, truncating long numbers, reading codes as dates), the detected types can be reviewed before import. Each column can be set to text, number, or date, together with the locale used to interpret it.
- [ ] **DATA-09 Transparent, movable data location** · QoL — Users can find where their data is stored. Where migration is needed, users can choose the directory or use a migration tool. With portable distribution, program and data stay together, and a portable copy used on several computers or by several users can keep separate data files per computer or per user; with managed installation, data is stored in the user directory. Large caches, indexes, and model files show their disk usage and can be moved off the system drive. Low disk space or an unwritable directory produces actionable feedback. The documentation states which directories can live in sync folders: a database in active use inside Dropbox or OneDrive risks corruption. Regenerable caches and temporary files have a cleanup policy (protection of the only copy of data inside a cache directory is covered by DATA-10), and temporary files left behind by a crash are removed on the next launch, except that content used for recovery is kept until the user has dealt with it. Rebuilding derived data and cleaning up orphaned files are covered by DATA-15.
- [ ] **DATA-10 Protection for bulk deletion and migration** · Baseline — Bulk-deleted items go to the trash or can otherwise be recovered. A failed data migration during upgrade can be rolled back. Before deleting or clearing synced or shared data, the application states whether the action affects this device, all of the user's devices, or what other participants see. If a cache directory holds the only copy of offline edits or unuploaded attachments, cache cleanup protects it as user data. Handling of an unreachable data location is covered by FILE-05.
- [ ] **DATA-11 Relocating external resources** · QoL — When a project that references external images, attachments, fonts, or assets is moved to another directory, drive, or computer, the references can be relinked, or dependencies can be bundled as needed. When a resource is missing, the user is asked to locate it first, and the reference record is kept. Moving or renaming a referenced resource within the application updates the references; when they cannot be updated, the affected references are listed first.
- [ ] **DATA-12 Handling growth in data size** · QoL — When large files, long histories, or very large numbers of objects exceed current capacity, the limitation is explained and batching, read-only opening, narrowing the scope, or export is offered, without endless loading; protection when only part of the content is loaded is covered by DATA-06. Opening a large file gives immediate feedback and shows what can be displayed without waiting for full indexing.
- [ ] **DATA-13 Handling corrupted data files** · Baseline — Corruption of a database, configuration, or document is detected on launch or open. The corrupted file is never overwritten with empty defaults. Restoring from a backup or exporting the readable parts is offered, and the application does not enter a crash loop. Rebuilding derived data is covered by DATA-15.\
  Common failure: After a failed load, defaults are written straight back to disk, wiping out years of user data.
- [ ] **DATA-14 Unfinished work is discoverable after leaving** · QoL — Objects with drafts, unsaved changes, failed sends, or content waiting to sync are marked in the list, tree, tabs, or sidebar, or collected in one place, from which the user can continue or retry. The marker disappears once the work is completed or discarded. A newly created object that was never edited is not marked as unfinished.\
  Common failure: The user writes half a reply in conversation A and switches away; nothing in the conversation list shows that A has a draft, and the reply is never sent.
- [ ] **DATA-15 Maintaining derived data and orphaned files** · QoL — Derived data such as caches, indexes, thumbnails, and statistics can be rebuilt from the UI; a rebuild only reads the original data and never modifies or deletes it (for the recovery entry point, see HELP-07). Attachments, backups, and thumbnails no longer referenced by any object can be scanned and listed by type with their location, size, and risk; the cleanup can be previewed beforehand and its result recovered (see DATA-10).\
  Common failure: After switching tokenizers, every conversation still shows the old statistics, and with no way to recompute them the user deletes the database and starts over.

## FILE · Files and resources

- [ ] **FILE-01 Platform file dialogs and persistent access** · Baseline — System open, save, and folder selection dialogs are used. The last used directory is remembered. Cancelling changes nothing. In sandboxed environments (macOS App Sandbox, Flatpak), recent files and workspaces persist access grants rather than only paths, and a way to re-grant access is provided when a grant expires.
- [ ] **FILE-02 Recent files** · QoL — Recently used items can be reopened. Stale paths are handled. The list can be cleared. The system's recent documents and jump lists are integrated. Files opened without the Open dialog, by drag and drop, double-click, or command line, also enter the recent list.
- [ ] **FILE-03 Paths, characters, and name collisions** · Baseline — Unicode user names, emoji, spaces, long paths, network paths, and symbolic links work. When syncing across systems, exporting to a directory, or batch renaming, names that differ only by case are never silently overwritten. File names that come from servers, archives, or batch jobs are sanitized by local rules: illegal characters, reserved names (CON, NUL), trailing spaces and dots, and length limits. Collisions after sanitizing can be previewed or are resolved explicitly. Automatically named outputs such as screenshots, recordings, and exports have a default file name that includes the source and the time, the naming template is configurable, and a sequence number is added on collision.\
  Common failure: Installation fails or the application errors on startup under a user directory with a Chinese name.
- [ ] **FILE-04 Feedback for move, rename, and delete** · Baseline — After an operation, the UI matches the actual state. Deletion prefers the trash; permanent deletion or an unavailable trash is stated clearly. Failures include a reason. In-app undo and the system trash are two separate recovery paths, and both are provided.
- [ ] **FILE-05 Network drives, removable media, and cloud placeholders** · Baseline — When storage disconnects, the application as a whole does not freeze, the user's work is preserved, and reconnect or save-as is offered. Online-only cloud files have a path but require a download for their content; opening, indexing, or batch processing such files does not misreport corruption, block without feedback, or trigger unexpected mass downloads. When a library, sync, or download directory becomes unreachable because an external drive was unplugged, a drive letter changed, or a network drive is not connected, "not found" is distinguished from "deleted": related tasks stop with a prompt to reconnect or relocate, the absence is not propagated as a deletion, and no empty library is created over the configuration. Before switching to an empty sync target, it is made clear whether this is a migration, a re-download, or a wipe.
- [ ] **FILE-06 Reveal in system** · QoL — Objects support "Show in file manager", copying the path, and opening with another program.
- [ ] **FILE-07 Encoding and format detection** `text` · Baseline — Text encoding and line endings are detected; when uncertain, the user chooses. BOMs are handled correctly. Lossy conversions are flagged.
- [ ] **FILE-08 File locks and stale lock files** · Baseline — Open files are not exclusively locked by default, so other programs can still read and sync them; when a lock is required, it is explained. Lock files left behind by a crash (`.lock`, `~$` files) are recognized and cleaned up on the next launch instead of being taken as proof that another instance is running. When a file is held by another program, that program is named. When a file or its directory is read-only, this and the reason are shown on opening; an attempt to edit offers a way to remove the read-only state or save elsewhere.\
  Common failure: A stale lock file remains after a crash, the application refuses to start, and the user has to find and delete the file by hand.
- [ ] **FILE-09 Browsing neighboring files in the same directory** · QoL — After a viewer or player opens a single file, the user can move forward and back through objects of the same kind in the same directory, and the types included are visible and adjustable. At the first or last object, stopping, wrapping around, or moving to the next directory is the user's choice and is indicated. After the current object is deleted or moved, the view lands on a neighboring object.\
  Common failure: After double-clicking an image, the arrow keys do nothing, and the only way to the next image is back through the file manager.

## TASK · Tasks, responsiveness, and resources

- [ ] **TASK-01 Cold start feedback** · QoL — A window or splash screen appears promptly after the icon is clicked. The product sets a target startup time and measures cold start, warm start, and activation of an existing instance separately. One-time preparation after a first launch or an upgrade (building a font cache, indexing resources) shows progress or an explanation. When startup is clearly slower than the target, the time spent on initialization, loading data, and each extension can be viewed and copied.\
  Common failure: Nothing happens for five seconds after a double-click, the user clicks twice more, and three instances start.
- [ ] **TASK-02 Status for long operations** · Baseline — The current operation is shown. When progress cannot be estimated, no precise percentage is displayed. Operations that finish quickly do not flash a loading indicator. Long tasks report their stage, such as receiving, verifying, processing, and delivering, and temporary space is included in disk space checks. Multi-step tasks share one overall progress bar that does not restart between steps and does not advance without real progress. Remaining time appears only once the estimate is stable. On completion, the output can be opened or located directly.
- [ ] **TASK-03 Stop waiting, cancel the task, or revert the result** · Baseline — Cancel is available in stages where cancellation is possible. A request may already have reached a server or external program, so the remote operation can still complete after the UI stops waiting; non-cancellable submission stages show their current state. Which intermediate artifacts are kept and which are cleaned up after cancellation follows a defined policy that is communicated to the user. Buttons distinguish Cancel (restore the previous state) from Stop (keep what is finished). After a sent message or email is recalled, its content returns to the editor.
- [ ] **TASK-04 Pause and resume** · QoL — Downloads, conversions, sync, and similar tasks can be paused and resumed. Resume information survives an application restart. Before resuming, the application confirms that the remote content is unchanged, and starts over explicitly when it has changed. Progress and resume information is written to disk at a stated interval, so a forced termination or power loss loses at most one interval of progress.
- [ ] **TASK-05 Retry and idempotency** · Baseline — Failed tasks keep their context. For actions with side effects such as uploading, creating, sending, or billing, the case where the remote operation succeeded but the response was lost is handled, and retries do not produce duplicates. When a temporary link expires, a mirror fails, or the service asks for a later retry, the task keeps its target and says so.
- [ ] **TASK-06 Entry point for background tasks** · QoL — Users can find running tasks, see their status, and choose to continue or stop them. The status says what is being processed and what triggered it. Quitting while tasks are running prompts and explains the consequences. Actions that are scheduled but not yet run, such as scheduled sends or planned tasks, can likewise be viewed, changed, and cancelled. When a task stops to wait for the user's confirmation while its window is in the background, a badge or notification says so, and the reminder is withdrawn once the user responds.
- [ ] **TASK-07 Interaction responsiveness** · Baseline — During long operations, the window can be moved, views can be switched, and the operation can be cancelled. While indexing, parsing, completion, or large tasks run, input and caret movement do not noticeably lag; when the application cannot keep up, it degrades gracefully and the UI does not freeze. There is no universal millisecond threshold; test with the product's typical documents and hardware.
- [ ] **TASK-08 Idle resource budget** · QoL — When the window is minimized, occluded, or hidden, activity that is no longer useful (animation, canvas redraws, high-frequency polling) stops or slows down, while user-requested continuous tasks (playback, recording, monitoring, transfers) continue. On low battery or in power saving mode, non-essential activity is reduced further. In background idle, CPU usage is near zero and memory does not keep growing. When the graphics backend fails, diagnostics or a fallback is available; whether GPU acceleration can be disabled is a product decision. When the GPU switches, the driver resets, or hardware decoding is unavailable, work is preserved and the application degrades gracefully. With several GPUs, settings show which GPU the application currently uses and allow choosing another, marking when the change requires a restart. The resource budget is set by the product according to its actual tasks. Visible idle, hidden idle, and continuous task states are tested separately.\
  Common failure: A lightweight utility sitting in the tray consumes about a third of a laptop's battery.
- [ ] **TASK-09 Sleep, wake, network, and device changes** · Baseline — After hours of sleep with the lid closed, or after switching Wi-Fi or VPN, connections recover automatically or reset cleanly without a cascade of error dialogs. When the audio output changes, headphones are plugged or unplugged, or the camera is in use elsewhere, the application returns to a selectable device or a recoverable state, and does not connect to a different device of the same kind just because it now holds the old position in the enumeration. After the system clock jumps, timeouts, retries, and duration calculations stay sane, and verification that depends on real time reports a clock problem rather than a generic failure.
- [ ] **TASK-10 Viewport behavior for streaming output** · QoL — While content is streaming or scrolling, scrolling up stops automatic scrolling to the bottom; scrolling back down or clicking "Jump to bottom" resumes following. A Stop button and shortcut are always available, and stopping keeps all content received so far, not only the part already displayed; effects such as character-by-character display affect only the pacing of display and can be turned off. For screen reader behavior, see A11Y-04.
- [ ] **TASK-11 Stale results do not override current intent** · Baseline — After searching for A and then B, or switching objects and previews in quick succession, an earlier request that returns late does not replace the current content. Results of old operations do not appear after the window closes. After switching accounts, responses for the previous account do not reach the new account's UI. Pressing Enter before suggestions have caught up with the input submits the current input.
- [ ] **TASK-12 Output after an interrupted long task** · QoL — After a recording, generation, or conversion is interrupted, the application states separately whether the main content is usable, whether secondary information (chapters, metadata) is complete, and whether processing can continue. The protection the current output format offers against interruption is explained.
- [ ] **TASK-13 Resource control during work** · QoL — While intensive tasks such as indexing, conversion, compression, or inference run, the user can lower concurrency or background priority so that other applications on the machine remain usable. Memory and disk usage is visible, limits can be set, and a warning appears as usage approaches a limit. Limiting transfer bandwidth is covered by TRANSFER-03.\
  Common failure: Background indexing saturates every core; the application itself stays smooth while a video call stutters for the duration.
- [ ] **TASK-14 Fault isolation of subsystems in use** · Baseline — When an independently recoverable subsystem such as preview, rendering, conversion, or a connection fails, other documents and unsaved content remain usable, and the user can locate the affected part and retry.\
  Common failure: One attachment crashes the preview process, the whole application exits, and edits in another document are lost with it.
- [ ] **TASK-15 Input version consistency for long tasks** · Baseline — Export, conversion, upload, and batch jobs operate on one defined version of their input. Editing or replacing the source while the task runs does not produce a result that is half old and half new.\
  Common failure: The user edits the document halfway through an export, and the resulting PDF has its first pages from one version and its last pages from another.
- [ ] **TASK-16 Actions after a task finishes** · QoL — For long tasks such as downloads, conversions, and playlists, a follow-up action can be chosen in advance: quit, shut down, sleep, run an external program, or delete the source objects. Shutdown and deletion apply only to the current task and are not kept as persistent settings. A cancellable countdown runs before execution. Verification before deletion and protection on failure are covered by DATA-06.\
  Common failure: "Delete the file after playback" is saved as a persistent setting, and the next day another video is deleted as soon as it finishes.

## NETWORK · Network, offline, and sync `network`

- [ ] **NETWORK-01 Connection state** · Baseline — Offline, connecting, service unreachable, and authentication failed are distinguished, and the indicator matches the actual state. Networks that require a captive portal sign-in, name resolution failures, and failures of the target service are distinguishable.
- [ ] **NETWORK-02 Timeouts and reconnection** · Baseline — Requests have timeouts. The reconnection process is understandable. Retries do not resubmit; for side-effect protection, see TASK-05.
- [ ] **NETWORK-03 Offline boundaries** · Baseline — When offline or when the session has expired, it is clear which data and actions remain available. Downloaded caches and local history can be viewed and searched. Uncommitted local work is protected. Local data is not hidden behind a full-screen sign-in prompt. The UI marks which content comes from cache and may be incomplete, and which authorizations will expire while offline.
- [ ] **NETWORK-04 Visible sync queue** · Baseline — Offline edits and pending uploads show their status. Before quitting, users can see what has not been uploaded yet.
- [ ] **NETWORK-05 Proxies and corporate networks** · QoL — The system proxy is followed, and HTTP/SOCKS5 can be configured manually. Self-signed certificates and restricted networks produce clear messages. Sign-in, the core API, images, downloads, the extension marketplace, and the updater may use different network stacks, and each one's proxy behavior is verified. The proxy configuration can test the connection, and addresses that bypass the proxy can be set. With several network interfaces, the outgoing interface and the IP protocol family can be chosen. When the user has pinned a proxy or interface and that path is unavailable, the connection stops with an explanation instead of falling back to a direct connection.
- [ ] **NETWORK-06 Data usage control** · QoL — Users control when large transfers and background updates run, including on metered connections.
- [ ] **NETWORK-07 Sign-in return path** · Baseline — After signing in through a browser, the user returns to the original window and task, with earlier input preserved. Only callbacks that match the current authorization request are accepted. Cancellation, timeouts, failed callbacks, duplicate callbacks, multiple instances, and account selection are handled. See Appendix A for implementation.
- [ ] **NETWORK-08 Transport encryption and server identity** · Baseline — Accounts, private content, and protected services travel over encrypted connections whose server identity is verified. When certificate verification fails, sensitive operations stop and the reason is shown; verification is never turned off automatically to keep sending credentials.\
  Common failure: Behind a corporate proxy the connection fails, the application silently disables certificate verification, and account credentials are then sent over that connection.
- [ ] **NETWORK-09 IPv6 networks** · Baseline — On IPv6-only networks, sign-in, core requests, and downloads work, with no hard-coded dependency on IPv4 addresses.\
  Common failure: Sign-in works, but in-app downloads fail permanently because of a hard-coded IPv4 address.

## SYSTEM · System integration

- [ ] **SYSTEM-01 Launch at login** `background` · Baseline — Can be turned on and off. The state shown in settings matches what is actually registered with the system. It is removed on uninstall. Verify with the final release package by signing out and back in once, confirming that the application starts or does not start as configured. An option to start minimized or hidden is available, and startup is deferred so that signing in is not slowed down.\
  Common failure: The setting is off, but the application still starts at login.
- [ ] **SYSTEM-02 Tray or menu bar entry** `background` · Baseline — Status can be viewed, the window opened, and the application explicitly quit. On Linux desktops without a tray, an alternative entry point is provided, so the process can always be found and quit. Tray and menu bar icons are legible on both light and dark bars (template images on macOS) and remain clear at 16 pixels. For handling a failed entry point, see SYSTEM-11.
- [ ] **SYSTEM-03 System notifications and attention** · Baseline — The system notification center is used. Do Not Disturb and the user's notification preferences are respected. Clicking a notification goes to the related object. Frequent successful actions get lightweight, local feedback instead of a toast each time. Important failures remain findable, with their state and actions, after the toast disappears. Similar events are grouped. Application sounds respect the system volume and mute setting and can be turned off in the application. Once the cause of a notification is resolved or handled elsewhere, displayed and queued notifications are withdrawn. While the application is in the foreground, in-app feedback is used instead. A persistent problem that needs the user's action is raised again periodically rather than repeatedly.
- [ ] **SYSTEM-04 Global shortcuts** `background` `on-demand` · Baseline — Configurable and can be disabled. The registration result reported by the system is checked, and "enabled in settings" and "actually active" are shown separately. A conflict is reported only when the cause is known; otherwise, changing the key, retrying, or an alternative entry point is offered. When hotkeys stop working because the foreground window runs as administrator or secure input is enabled, the reason and an alternative are explained where this can be detected. When an active hotkey stops working at runtime, its shown state updates, the application re-registers it automatically, and a manual reload entry point is offered. For hotkeys triggered by double-pressing a modifier, the interval is adjustable, and pressing another key in between does not trigger them. Pausing by foreground context is covered by SYSTEM-15.
- [ ] **SYSTEM-05 File associations and Open With** · Baseline — Users choose which file types to associate. Routing of externally opened files to windows is covered by WINDOW-05. The application appears in the system's "Open With" list. When an association is taken over by another program or points to a moved or uninstalled copy, it can be re-associated from inside the application, or the system's default apps settings can be opened from there. Links, email addresses, and files that the application hands off to other programs open in the programs the user has set as defaults.
- [ ] **SYSTEM-06 Protocols and deep links** · Baseline — Supported links go to the correct content. Parameters are validated, and unknown or malicious parameters are handled safely. External parameters are never interpreted as additional commands, launch options, or file operations.
- [ ] **SYSTEM-07 Taskbar and Dock** · QoL — The icon and name are easy to recognize. Long tasks show progress on the taskbar or Dock. Unread or pending items show a badge; counting and clearing follow SYSTEM-14. A jump list or Dock menu provides common entry points (on Linux, depending on the desktop environment).
- [ ] **SYSTEM-08 Preventing sleep** · Baseline — System idle sleep is prevented only during long renders, large transfers, playback, presentations, sync, or batch tasks, and the request is released on pause, failure, completion, or exit. The request applies only to idle sleep; closing the lid, manual sleep, and shutdown proceed normally. Video playback and presentations also prevent the display from turning off; audio playback, downloads, and sync prevent only system sleep and do not keep the screen on. Persistent changes to system settings are covered by SYSTEM-13.
- [ ] **SYSTEM-09 Sharing, printing, and system services** · QoL — Where applicable, system sharing, printing, and quick preview are integrated, and unavailability or cancellation is handled correctly. Before printing, the target, paper, and range can be confirmed; handing the job to the system queue is distinguished from actual completion; retrying after a failure does not submit the job twice.
- [ ] **SYSTEM-10 Command-line entry** · QoL — The application can be opened from a terminal with `app file` or `app .`, and `--help` and `--version` work. Invocations are routed to the appropriate instance according to the product's window model. When a new instance, waiting for completion, or headless execution is needed, the arguments and output behavior are documented. For task automation, see AUTOMATE.
- [ ] **SYSTEM-11 Alternatives when system features are unavailable** `background` `on-demand` · Baseline — When hotkey registration fails, the tray is not shown, notifications are disabled, or desktop portals are unavailable, the window can still be reopened and the application quit through the application icon, a menu, or the command line. Failures that can be detected are reported first.
- [ ] **SYSTEM-12 Shutdown, sign-out, and system restart** · Baseline — On a system shutdown or sign-out notification, state is saved quickly and the application exits. When blocking shutdown is unavoidable, the reason is shown. After a restart for a system update, the application can register to relaunch and restore its session. See Appendix A for implementation.\
  Common failure: The application blocks shutdown without saying why, and the user sees only "An app is preventing shutdown".
- [ ] **SYSTEM-13 Restoring changes to system-wide settings** · Baseline — When the application changes system-wide settings such as the system proxy, power settings, Do Not Disturb, or the default audio device, the original settings are restored after a normal exit, a crash, or a forced termination. Before restoring, the application checks that the current value is still the one it set; if the user or another program has changed it since, the current value is kept and the user is told. When automatic restoration is not possible, the next launch detects the leftover change and tells the user. Idle sleep requests are covered by SYSTEM-08.\
  Common failure: After a proxy client is force-quit, the system proxy still points to a closed local port and the whole computer loses internet access.
- [ ] **SYSTEM-14 Accurate unread and pending state** · QoL — In products with an unread state, content is marked as read only when it appears in an active, unlocked window. Reopening can jump to the first unread item, and items can be marked unread again by hand. Once handled, in-app markers, taskbar or Dock badges, and the related system notifications clear together. Multi-device products sync read state and offer a way to fix it when it falls out of sync.\
  Common failure: The channel opened automatically at startup has hundreds of unread messages cleared at once, and the user never learns what was missed.
- [ ] **SYSTEM-15 Global features pause by foreground context** `background` `on-demand` · QoL — Features that act globally, such as hotkeys, mouse gestures, clipboard monitoring, and text expansion, can be excluded per application and can be set to pause automatically when the foreground window is full screen or a game, or when a remote desktop or virtual machine window is in front, so that host and guest do not both respond. A global pause is available, the paused state is recognizable on the tray icon, and another entry point remains (see SYSTEM-11).\
  Common failure: The same clipboard tool is installed on the host and inside the remote desktop, and a double-press of Ctrl opens a window on each side.

## INSTALL · Installation, updates, and uninstallation `distribution`

- [ ] **INSTALL-01 Installation scope and first launch** · Baseline — The installation scope suits the target users and channel: when per-user installation is possible, administrator rights are not requested; when elevation is required, the reason is given. Installers that offer a custom path accept reasonable paths. A failed first installation rolls back the registrations and services it created. On first launch, the data location and required permissions are explained, and running elevated is flagged with its side effects: on Windows, dragging in from non-elevated programs such as File Explorer is blocked, running as a different administrator account writes configuration to that account's profile, network drives mapped under standard rights are not visible to the elevated process, and programs started from the application also run as administrator. For signing and system gatekeeping, see INSTALL-12.
- [ ] **INSTALL-02 Versions and update responsibility** · Baseline — The current version is visible. Who handles updates and how users are informed follows the conventions of the current distribution channel. With app store and package manager distribution, the channel usually handles updates; when the application updates itself, this is declared according to the channel's rules (for example, `auto_updates` in a Homebrew Cask).
- [ ] **INSTALL-03 Update preferences** · Baseline — Within what the channel and management policies allow, update behavior is understandable and controllable: when the application manages its own updates, it offers options such as automatic, notify, and manual; in managed environments, it shows who is responsible. Checks and downloads run in the background. No forced restart happens while the user is editing or running a task. "Finish update on next quit" is supported. Installing an update on quit does not relaunch the application by itself, and a restart after a silent update keeps the previous tray, hidden, or minimized state.
- [ ] **INSTALL-04 Usable after a failed update** · Baseline — Check, download, install, and failure states are visible. After a failed update, the previous version continues to work.
- [ ] **INSTALL-05 Program rollback and data downgrade** · Baseline — When an older version opens data written by a newer version, it refuses clearly, opens read-only, or enters a recovery flow, and the data is not damaged. When a safe downgrade is not possible, the reason is stated and a way to keep a copy is provided. Rolling back a failed data migration during upgrade is covered by DATA-10.
- [ ] **INSTALL-06 Uninstallation scope** · Baseline — Startup entries, file associations, services, global shortcuts, and context menu entries are removed, along with bundled helper services, downloaded resources, and private fonts. Users choose whether to keep or delete user data and know the exact scope. Files the user created, shared components, and other versions on the same computer are not affected. Reinstalling does not lose data.
- [ ] **INSTALL-07 Update authenticity** · Baseline — When the application updates itself, update packages are verified against a public key built into the application, and a package whose signature does not match is refused. The version manifest is signed as well, binding each version number to its package digest; rollback protection compares signed version information, so neither the server nor an intermediary can steer users onto an older, vulnerable release. See Appendix A for implementation.\
  Common failure: Updates rely on HTTPS alone, and a tampered manifest downgrades users to a version with a known vulnerability.
- [ ] **INSTALL-08 Update download and installation** · Baseline — Disk space is checked before downloading, interrupted downloads resume, and the hash is verified before installing. Files of the running program can be replaced, or the replacement completes after quit or on the next launch. When the install location is not writable by the current user, there is an elevation or alternative path rather than a silent failure. Whether copies installed through an app store or package manager update themselves follows the channel's rules (see INSTALL-02).\
  Common failure: The updater tries to overwrite the running executable, fails with "file in use", and leaves half of the new files behind.
- [ ] **INSTALL-09 Runtime dependencies on a fresh system** · Baseline — On a clean installation of a supported system, the final release package installs and completes the first core task. Required runtimes (WebView2, the VC++ runtime, .NET, Java, Python, GTK) are checked and installed by the installer, or their name, purpose, and download path are shown when missing.\
  Common failure: The development machine has Python, so the release package ships without the runtime, and nothing appears when the user double-clicks the icon.
- [ ] **INSTALL-10 Running from a read-only or protected location** · Baseline — Launched from a DMG, a network share, a read-only mount, or Program Files as a standard user, the application runs normally and writes its state to a user-writable location. When moving or installing is required, the reason and the steps are explained (on macOS, a prompt to drag to Applications).\
  Common failure: Launched directly from a DMG, the application tries to create its database next to the executable and the first launch sits on the loading screen forever.
- [ ] **INSTALL-11 Processor architecture** · Baseline — The application runs natively on Apple Silicon, Windows on ARM, and Linux aarch64, or clearly states that it runs under emulation. The installer and updater pick the architecture that matches the system, and bundled helper executables also run natively or are declared to run under emulation.\
  Common failure: The main program is arm64 but ships an x64 FFmpeg, which runs under emulation on Windows on ARM at a fraction of native speed.
- [ ] **INSTALL-12 Signing, source verification, and system gatekeeping** · Baseline — The download source and publisher can be verified. On Windows and macOS, every executable, including helpers, the updater, and the uninstaller, is signed; on Linux, the package or repository is signed. System gatekeeping such as SmartScreen and Gatekeeper is explained with the correct steps to proceed; a newly signed release may still trigger a SmartScreen warning until it builds reputation. When a component is quarantined by security software, the affected component and a trusted repair path are named.\
  Common failure: The main program passes SmartScreen, but the first call to an unsigned transcoding helper shows an "Unknown publisher" warning.

## PRIVACY · Permissions, accounts, and privacy

- [ ] **PRIVACY-01 Task-based permission requests** · Baseline — Permissions are requested only when needed, with what is accessed and why. After the user declines, the remaining features still work.
- [ ] **PRIVACY-02 Handling revoked permissions** · Baseline — After access is revoked through macOS privacy settings, Linux sandbox portals, or folder grants, the user is notified and given a way to grant it again.
- [ ] **PRIVACY-03 Credential storage** · Baseline — Secrets and session tokens are stored in the system keychain or credential manager (Windows Credential Manager, macOS Keychain, Linux Secret Service) and do not appear in logs, exported files, screenshots, or the UI in plain text. When the keyring is locked, missing, or fails to decrypt after migration, "use for this session only" or signing in again is offered; secrets are never silently written to an ordinary configuration file instead. Credentials do not appear in helper processes' command-line arguments or in error output, and saved credentials are used only for the service they were granted to, so they are not forwarded when following a redirect or switching mirrors. On Linux, the actual level of protection depends on the available secret store backend.
- [ ] **PRIVACY-04 Transparent, optional telemetry** · Baseline — What is sent and why is explained. Defaults are reasonable. The current state can be checked, and telemetry can be turned off at any time. Connections the application initiates on its own without user content (update checks, extension lists, online resources) likewise list their purpose and how to turn them off, and products that work mainly locally offer a master switch for network access. Server-controlled feature experiments are explained separately from telemetry, and the experiments currently in effect can be viewed and opted out of. Crash report contents and redaction are covered by HELP-05.
- [ ] **PRIVACY-05 Signing out and switching accounts or workspaces** `network` · Baseline — Ownership of drafts, pending sync items, downloads, and local caches is clear. Unfinished work is visible before switching. For late responses from the previous account, see TASK-11.
- [ ] **PRIVACY-06 Viewing, exporting, and deleting account data** `network` · Baseline — Entry points are provided, and the scope of each action is explained.
- [ ] **PRIVACY-07 Displaying and copying sensitive content** · QoL — Sensitive content can be hidden in notification previews, history, and sharing UIs. After a password or token is copied, the timed clear removes only what the application itself placed on the clipboard and keeps anything the user copied afterward. Such content can be excluded from system clipboard history and cloud sync where needed, and the extent of the protection is explained. Windows with a clear privacy need can be excluded from screen sharing and window previews where the platform allows, with the scope of that protection stated. Search, run, and similar histories can be cleared by category and set to clear automatically on quit; stopping recording does not delete existing records, and clearing has its own entry point. App lock is covered by PRIVACY-13.
- [ ] **PRIVACY-08 Transparent cloud processing** `network` · Baseline — Users know which content leaves the device and where it goes, and can choose or stop it. The processor and processing region are identifiable, and data sent by third-party components is covered by the same disclosure and controls.
- [ ] **PRIVACY-09 Access boundaries of local services and IPC** · Baseline — Internal local services and inter-process communication accept connections only from their intended callers. Web pages, devices on the local network, and other users on the same computer cannot use them to read data or perform actions. Startup does not trigger a firewall prompt. See Appendix A for implementation.\
  Common failure: The service connecting the UI to the download engine listens on all interfaces without authentication, and other devices on the LAN can add tasks.
- [ ] **PRIVACY-10 When and why the clipboard is read** · Baseline — The clipboard is read only when the user pastes or has explicitly enabled a feature that needs it. Continuous clipboard monitoring has a visible state and an off switch, and what is read is used only for the stated purpose.\
  Common failure: A background tool reads the clipboard continuously to detect links and uploads a just-copied password as a diagnostic event.
- [ ] **PRIVACY-11 Hidden information in exports and shares** · QoL — Before exporting, publishing, or sharing, users can see and remove metadata that travels with the result: location, author, revision history, comments, and hidden content. In products that offer redaction, redacted text and images are removed from the shared copy and cannot be recovered by copying, searching, removing an overlay, or extracting embedded content. Redactions that are marked but not yet applied are visually distinct from applied ones.\
  Common failure: The user removes their name from the document, but the exported file still carries the author field and comments with the name.
- [ ] **PRIVACY-12 Terms and privacy policy remain accessible** · Baseline — Users can read the full text before accepting terms or providing data, can reach it again from within the application afterwards, and can tell which version applies.\
  Common failure: The privacy policy appears once in a first-launch dialog and has no entry point after it is dismissed.
- [ ] **PRIVACY-13 Scope of app lock protection** · Baseline — In products with an app lock, locking protects the main window, secondary windows, quick panels, window previews, and notification previews. Idle time is measured from system-wide input. The app locks along with the system lock screen or sleep, and unlocking returns to the previous work.\
  Common failure: The main window is locked, but the quick panel still shows recent conversations and the taskbar preview still shows the screen from before locking.

## HELP · Help, feedback, and diagnostics

- [ ] **HELP-01 First-run guidance** · QoL — Users can complete their first core task. Guidance can be skipped and viewed again.
- [ ] **HELP-02 Empty states that suggest a next step** · QoL — Empty lists, no results, and unconfigured states tell users what they can do next. "Not found" is distinguished from "search incomplete": indexing in progress, sync in progress, insufficient permissions, scope too narrow, and genuinely absent each get a different message.
- [ ] **HELP-03 Actionable, copyable error messages** · Baseline — Error messages state what failed, why, and what can be done, with recovery actions available right there (retry, save elsewhere, check proxy, open the relevant setting in the app or in system settings, copy details). Technical details can be expanded and copied. When a file fails to open, a corrupted file, a missing component, and a format the current distribution does not support are distinguished. When a save is refused by controlled folder access, security software, or a cloud drive client, the error message names that possibility and explains how to add an exception. When a button, menu item, or setting is unavailable, the reason and the condition for enabling it can be found; when the condition is a setting, that setting can be opened directly.\
  Common failure: An error dialog shows only "An error occurred (code -1)".
- [ ] **HELP-04 Help that matches the version** · QoL — Help, FAQ, and documentation links correspond to the current version.
- [ ] **HELP-05 Diagnostic logs and bundles** · QoL — The log directory can be opened. A diagnostic bundle can be exported, its contents are described, and it can be previewed or scoped before sending. Redaction covers tokens, paths, search terms, configuration, personal dictionaries, screenshots, and crash dumps. Local logs and crash dumps are likewise controlled for sensitivity and retention; logs rotate and have a size cap. The diagnostic bundle lists the names and versions of bundled components. When the window never appears, the startup error can be obtained through a launch entry point with a console, a debug launch script, or a startup log, and the documentation states where to find it.
- [ ] **HELP-06 Feedback entry point** · QoL — Feedback can include environment information, and users can review the content before sending.
- [ ] **HELP-07 Safe mode and self-recovery** · Baseline — When extensions, themes, configuration, or GPU acceleration prevent the application from working, it can start with a minimal configuration (via a command-line argument, or by prompting after repeated failed launches) without touching user data. Recovery proceeds in three steps: temporary isolation first, then targeted disabling, and broad resets only as a last resort. Leaving temporary mode restores the original environment. Products with many extensions offer bulk disabling or bisection, and restore the original state when troubleshooting ends. Rebuilding derived data is covered by DATA-15, and troubleshooting third-party injected modules by HELP-10.
- [ ] **HELP-08 What's new after an update** · QoL — On first launch after an upgrade, a single lightweight entry point explains what changed, especially changes to default behavior or shortcuts. It can be dismissed, viewed again from the Help menu, and does not appear on every launch. When the interface or default behavior changes substantially, an option to return to the previous version is kept for a transition period, with notice before it is removed.\
  Common failure: An update changes a frequently used shortcut, and users assume the application is broken.
- [ ] **HELP-09 Samples and templates** · QoL — An empty workspace offers sample documents, sample projects, or templates, so users can see what the application does without starting from a blank state. Samples can be removed in one action and are kept separate from user data.
- [ ] **HELP-10 Third-party injected modules and interfering software** · QoL — When third-party software that injects into the process or hooks system APIs (screen overlays, pop-up dictionaries, sandboxes, security software, shell extensions, outdated tablet drivers) causes a blank window, a crash, a freeze, or a hang at startup, the help documentation maintains a list of known conflicts and how to handle them. A diagnostic tool lists the third-party modules loaded into the process with their vendors, marks common sources of conflict, and gives instructions for adding an exception rather than only recommending that security software be turned off. The diagnostic bundle (HELP-05) includes this list.\
  Common failure: Another program's pop-up dictionary freezes the application at random, the troubleshooting page's only advice is "temporarily disable antivirus software", and on a corporate computer the user lacks that permission.

## FIND · Search and filtering

Applies to products with many items, objects, commands, or records. Related items: command palette INPUT-05, settings search SETTINGS-02, "not found" versus "search incomplete" HELP-02, cross-view restoration WINDOW-06.

- [ ] **FIND-01 Visible scope and exclusions** · Baseline — While searching or filtering, the current scope (current file, current library, whole project) and active exclusions are shown. When there are no results, the scope can be checked or widened.\
  Common failure: A "current folder only" filter left over from the last session is not shown, and the user cannot find a file that exists.
- [ ] **FIND-02 Recognizable matches, navigable results** · QoL — Results show enough path, context, or match location to tell objects apart. Results can be traversed, opened, and returned from with the keyboard, landing on the match location. Refreshing results does not change the current selection. After a result is opened, the object can be revealed in the application's own folder or tree view.\
  Common failure: Ten results are all named "Note" with no path or snippet; pressing "Next" jumps back to the first result.
- [ ] **FIND-03 Visible matching mode** · QoL — Fuzzy, exact, case-sensitive, regular expression, and other modes are supported as the product requires, and the current mode and filters are visible. Unsupported syntax is explained, and input that cannot be parsed is shown as a syntax error. For multilingual writing variants, see LOCALE-05.\
  Common failure: Regex mode from last time is still active, a search for a file name containing parentheses fails, and nothing in the UI shows why.
- [ ] **FIND-04 Repeated searches** · QoL — Products used for frequent searches keep recent queries, allow pinning common conditions, and allow copying results. Restored query conditions are recognizable and can be cleared quickly. Retention and clearing of sensitive queries match the product's privacy expectations. Clearing histories by category is covered by PRIVACY-07.\
  Common failure: On a shared computer, the previous user's sensitive searches are restored automatically.
- [ ] **FIND-05 Personal markers for later** · QoL — Products where users return repeatedly to specific objects or locations let them mark an object, paragraph, or line and go straight back to it from one place. Removing a marker does not delete the content.\
  Common failure: A message that was read but not yet handled is buried among read messages, and finding it again depends on memory.

## TRUST · Untrusted content

Applies to products that open files, projects, email, or web fragments from unknown sources. This domain covers what opening content grants. Related items: the application's own permissions and data PRIVACY, incoming deep links SYSTEM-06, installer origin and system gatekeeping INSTALL-12.

- [ ] **TRUST-01 Restricted view first** · Baseline — Documents or projects with active content open in a restricted mode first, and the user is told which capabilities are suspended. Generating thumbnails or previews does not run tasks from the content. When safe preview is not possible, the limitation is explained.\
  Common failure: A user opens a downloaded project to read its README, and a command in the project configuration has already run.
- [ ] **TRUST-02 Clear scope of trust** · Baseline — When macros, scripts, or project tasks need additional trust, the scope of the grant is stated: this time only, this file, this folder, or this publisher. After declining, safe reading remains available. Granted trust can be reviewed. "Allow editing" and "allow execution" are granted separately.\
  Common failure: After clicking "Allow" once for a document, every new script in the same folder runs automatically, and the UI says nothing about it.
- [ ] **TRUST-03 Network requests from untrusted content** `network` · Baseline — Remote images, styles, and other external resources in email, documents, and previews follow the privacy settings the product declares. When blocked, the missing content is indicated and the scope of any allowance is clear. When offline, the available parts are still shown.\
  Common failure: The user turned off telemetry and expects previews not to go online, but tracking images in email still load.
- [ ] **TRUST-04 Verifiable link targets** · Baseline — The real target of links in untrusted content can be viewed or copied. When the displayed text does not match the target, an external program would be launched, or a high-risk protocol is involved, a warning appropriate to the risk is shown. If the target is abnormal or the user cancels, the view stays on the original content. Ordinary links do not get an extra confirmation.\
  Common failure: A preview displays an official sign-in URL, clicking it opens a different domain, and the user has no way to check the target beforehand.
- [ ] **TRUST-05 Directory boundary on archive import** · Baseline — When importing themes, plugins, backups, project bundles, or other archives, content is written only inside the directory the user chose. `../` paths and symbolic links inside the archive cannot write outside it or replace other files. See Appendix A for implementation.\
  Common failure: A theme package contains `../` paths that overwrite the application's configuration and the user's shell startup script.
- [ ] **TRUST-06 Handing over origin marks on downloaded content** · QoL — Internet content saved by the application carries the platform's origin mark (Mark of the Web on Windows, the quarantine attribute on macOS), so opening it with another program still goes through the system's trust checks.\
  Common failure: A document downloaded by the browser opens in Protected View, while the same document downloaded by the application loses its origin mark and opens with full permissions.

## EXTEND · Extensions and plugins

Applies to products with community plugins, script packages, executable themes, or an extension marketplace. Related items: temporary isolation when the application fails to start HELP-07, organization-managed extensions MANAGED-05.

- [ ] **EXTEND-01 Actual permissions and trust boundaries** · Baseline — Before installation, the extension's actual access, whether it runs in isolation, and the trust implications are explained. Only technically enforced restrictions are described as isolation or sandboxing; declared-only permissions are presented as full trust. If the user declines to install or run an extension, the main application works normally.\
  Common failure: The install screen lists only "Read the current note", while the plugin can actually read and write the user's other files and access the network.
- [ ] **EXTEND-02 Identifiable origin and dependencies** `distribution` · Baseline — Users can confirm an extension's identifier, publisher, source, and bundled dependencies. The publisher's verification status is shown so extensions with similar names can be told apart. Failed signature or source verification produces clear feedback.\
  Common failure: Installing a theme also installs several extensions that can run code, without telling the user.
- [ ] **EXTEND-03 Controlled updates** `distribution` · QoL — Products with many extensions provide update controls, compatibility notices, and a recovery path. A failed upgrade leaves a working environment. Before rolling back to an older version, data and settings compatibility is stated. When an update widens what an extension can do, for example from a pure theme to one with executable code, consent is asked again.\
  Common failure: The main application is unchanged, but an extension updates overnight and projects no longer open; the user cannot tell which extension changed or disable it.
- [ ] **EXTEND-04 Effects of disabling and removal** · Baseline — Users can disable or remove extensions and know when the change takes effect and which settings and document dependencies remain. Disabling does not delete user data. Required restarts or follow-up cleanup are indicated.\

## AUTOMATE · External automation

Applies to products involving repetitive export, conversion, organization, or query work; this includes screenshot tools and launchers with repeated operations. Available paths include command-line arguments, system actions (Shortcuts, D-Bus), scripting interfaces, drivable UI (UI Automation), and agent interfaces (such as MCP), chosen according to the product. For terminal launch and window routing, see SYSTEM-10. Good assistive technology semantics (A11Y-03) also help external automation.

- [ ] **AUTOMATE-01 Composable entry points for repetitive tasks** · QoL — Command-line arguments, system actions, scripting interfaces, or drivable UI are provided per task and can perform real work such as queries, conversion, and export, beyond opening a window from a terminal. Unsupported actions are documented.\
  Common failure: The batch entry point only opens one window at a time, and format selection and confirmation still take hundreds of manual clicks.
- [ ] **AUTOMATE-02 Precisely addressable objects and actions** · QoL — Objects exposed to external tools have stable identifiers, names, states, and available actions. After a rename, view change, or reordering, actions still apply to the original object. When identification fails, the operation stops or asks for confirmation.\
  Common failure: A script always clicks "Delete" on the seventh row; after the sort order changes, it deletes a different object.
- [ ] **AUTOMATE-03 Determinable input, output, and completion** · Baseline — Automatable entry points define the input scope, output location, and how completion and failure are reported (exit codes, result files). Steps that require interaction are documented, and unattended runs do not wait on hidden dialogs. Partial success is identifiable. For side-effect protection on retry, see TASK-05.\
  Common failure: A failed conversion only prints an error message, the caller treats it as success, and the next run overwrites the original file.
- [ ] **AUTOMATE-04 Delegation that can be enabled, stopped, and reviewed** · Baseline — Control services or interfaces for sensitive operations are off by default or enabled by the user. Enabled state, caller identity, and active grants are visible and can be revoked or stopped. Connection failures or expired grants do not widen permissions. Ordinary script actions do not need per-action confirmation. Rules for data leaving the device are covered by PRIVACY-08; callers of a local service may send content to remote models, and this is stated when the service is enabled.\
  Common failure: After the user tries an agent feature once and quits the client, the local service keeps running and there is no way to revoke it.

## LICENSE · Licensing, trials, and expiration

Applies to products with trials, subscriptions, device seats, or version-based licenses. This domain covers changes in functionality caused by changes in entitlement; for general export, see DATA-08.

- [ ] **LICENSE-01 License state and available scope** `distribution` · Baseline — Users can see their current license, which versions and features remain available after expiration, and where to renew or buy. When a trial ends, a clear license state is shown.\
  Common failure: A user who bought a perpetual license for an older version sees only "Invalid license" after upgrading and cannot find the version they are entitled to.
- [ ] **LICENSE-02 Retrieving existing work after expiration** `data` · Baseline — When a license expires or is downgraded, users keep a way to view, copy, or export within the access they still have, with time limits, attachments, and lossy parts stated. Content that requires an active service is disclosed in advance. Expiration, authentication failure, and revoked access are shown as different states.\
  Common failure: When paid editing features expire, the user's own local projects and the export function are locked as well.
- [ ] **LICENSE-03 Handling failed verification** `distribution` · Baseline — Features that can work offline have offline verification, a grace period, or clearly stated limits. When the license service is unreachable, network failure is distinguished from an invalid license, and the application does not close in the middle of a save. Whether fully offline activation is offered is a product decision.\

- [ ] **LICENSE-04 Changing or losing devices** `distribution` · QoL — When the number of devices is limited, users can view and release old devices and move to a new one. If an old device is broken or lost, remote deactivation or a support path is available. A failed transfer states whether the cause is seats, version, or identity. Purchases made through an app store can be restored after reinstalling or changing devices, and a mismatch between the store identity and the application account is explained.\

## MANAGED · Organizational deployment and managed environments

Applies to products that companies, schools, or computer labs install in bulk, lock down, or update centrally. Products that support only individual installation can skip this domain; for session isolation on ordinary shared computers, see WINDOW-05. For proxies and corporate certificates, see NETWORK-05.

- [ ] **MANAGED-01 Unattended deployment** `distribution` · Baseline — Products that support bulk deployment can be installed, upgraded, and uninstalled through documented non-interactive methods. Administrators receive the result, failure reasons, and restart requirements. No dialogs are shown in sessions where no user is signed in.\
  Common failure: The management system reports that the command ran, while the installer is actually waiting in a hidden window for someone to click "Next".
- [ ] **MANAGED-02 User and machine scope** `distribution` · Baseline — When multiple installation scopes are supported, it is stated which scope the program, settings, data, services, and updates each belong to. If elevation fails, the user can exit or choose a permitted scope. Different users on the same computer do not use each other's data by mistake; isolation of instances between sessions is covered by WINDOW-05. See Appendix A for implementation.\
  Common failure: After an administrator installs the program, a standard user's configuration is written to the administrator's personal directory.
- [ ] **MANAGED-03 Visible policy control** `distribution` · Baseline — Settings controlled by organizational policy show that they are managed and display the effective value. When a user change conflicts with policy, the UI states that the change did not take effect. A way to get help or more information is provided.\
  Common failure: "Automatic updates" can be checked every time, reverts after a restart, and no managed notice is shown.
- [ ] **MANAGED-04 Complete path for isolated networks** `distribution` · Baseline — Products that support isolated networks provide offline sources that can be prepared in advance for runtimes, feature packages, licenses, and essential help. When a component is missing, the application states what is missing and does not switch to an online download. The extent of offline help is a product decision.\
  Common failure: The full installer can be copied into the internal network, but the first launch still requires downloading a runtime, activating online, and opening online help.
- [ ] **MANAGED-05 Consistent maintenance responsibility and extension sources** `distribution` · Baseline — When an organization manages versions or extension distribution, users can identify the maintainer and the available update sources. Blocked extensions show the reason, are not installed around the policy, and are not retried endlessly.\
  Common failure: The main program is pinned to a fixed version, while a built-in extension updates itself to an incompatible version that standard users have no permission to fix.

## FAIR · Respecting user choice

Applies to products with accounts, promotions, payments, or bundled installation.

- [ ] **FAIR-01 Account requirements proportional to features** `network` · QoL — Local features that do not depend on an account can be used directly; sign-in is requested at the point of sync, collaboration, or licensing. After skipping sign-in, there is a clear path to continue, and "Sign in later" does not repeatedly block the user.\
  Common failure: A user who only wants to view local files has to verify an email address before entering a viewer that could work offline.
- [ ] **FAIR-02 Installation and updates respect prior choices** `distribution` · Baseline — Bundled components, file associations, default programs, and launch at startup are disclosed and left to the user's choice. Declining bundled components does not cause installation to fail. Updates do not re-enable options the user turned off. Preinstalled components the user removed are not reinstalled after a restart or update, and a specific version the user installed by hand is not overwritten by automatic updates by default.\
  Common failure: File associations were declined during installation, and the next minor update takes over every file type again.
- [ ] **FAIR-03 Dismissible promotions, remembered refusals** · QoL — Upgrade, trial, rating, and referral prompts do not cover current work and do not imitate system warnings. Dismiss and decline options are easy to find, and prompts do not repeat when nothing has changed. Essential security notices are separate from marketing preferences.\
  Common failure: The user dismisses the same promotional dialog every day, and its close button is relabeled "Miss out on this offer for now".
- [ ] **FAIR-04 Findable cancellation, exit, and uninstall** `distribution` · Baseline — Users can find how to cancel a subscription, stop background activity, and uninstall, and know when billing stops and which services and data are affected. A workable path exists when payment fails or the purchase was made through a different channel, without requiring users to accept unrelated promotions first. For uninstallation cleanup, see INSTALL-06.\
  Common failure: Cancellation is available while payments succeed, but once the card expires the cancel button disappears and only "Pay outstanding balance" remains.
- [ ] **FAIR-05 Clear pricing, trial, and renewal terms** · Baseline — Before confirming a purchase or starting a trial that leads to charges, the user can see the actual amount charged, the billing period, the price after the trial, and the automatic renewal terms.\
  Common failure: The purchase button highlights a monthly equivalent price, and pressing it charges a full year at once.

## COMPONENT · Bundled components and helper processes

Applies to products that ship external components such as FFmpeg, aria2, a Python or Node runtime, fonts, dictionaries, codecs, or models, or that start helper processes. For runtime dependencies at install time, see INSTALL-09; for the architecture of helpers, see INSTALL-11.

- [ ] **COMPONENT-01 Coexistence with system copies** · Baseline — The application uses the component version it declares support for. A tool of the same name appearing on the system PATH does not change the application's behavior, and the application does not replace or break the system's copy.\
  Common failure: After the user installs another program, the application starts calling an incompatible FFmpeg from PATH and every existing export format fails.
- [ ] **COMPONENT-02 Acquiring and removing on-demand resources** · QoL — When a feature needs an additional download such as a model, codec, or language pack, the purpose, size, and location are stated beforehand. Users can see readiness, retry the download, and remove resources they no longer need. Resources placed in advance work offline.\
  Common failure: Clicking the recognition button immediately starts a multi-gigabyte model download with no explanation and no way to cancel or uninstall it.
- [ ] **COMPONENT-03 Identity and lifetime of helper processes** · Baseline — After the main program quits normally or is killed, no helper processes that run with it remain. Components meant to keep running (the updater, user-approved background downloads, system services) are identifiable, have an exit condition, and can be managed from an entry point. In the task manager and the volume mixer, helper processes have recognizable names, descriptions, and icons attributed to the application. When a helper crashes, the main program keeps running and reports it. See Appendix A for implementation.\
  Common failure: Six `node.exe` processes keep running after the application is closed, and the user cannot tell which program they belong to.
- [ ] **COMPONENT-04 Third-party licenses and notices** · Baseline — Copyright and license notices for bundled components and resources can be found in the application. Where a license such as GPL or LGPL requires source availability, a way to obtain it is provided.\
  Common failure: The application ships FFmpeg and fonts, and neither the About page nor the installer contains any license text.

## TRANSFER · Delivering transfer results

Applies to products that download, upload, sync, or fetch large resources. For pause and resume, see TASK-04; for retries, see TASK-05; for data usage control, see NETWORK-06; for file name handling, see FILE-03.

- [ ] **TRANSFER-01 Integrity verification** · Baseline — When verification data is available (hash, signature, length), the result is verified after transfer. A file that fails verification is never put into use as a successful result.\
  Common failure: The download shows as complete but is missing a segment, and the application immediately loads the damaged model as the default.
- [ ] **TRANSFER-02 Boundary between partial files and final results** · Baseline — Files in transfer use a temporary name (for example `.part`). The final name appears only after receiving, assembling, and verifying are complete, so other programs never open a half-written file.\

## Appendix A · Implementation notes

Implementation details that need extra attention, listed by item ID.

**General**

- DATA-06, SETTINGS-04: Write to a temporary file in the same directory, fsync it, and atomically replace the target. On POSIX, use `rename`, then fsync the containing directory; on macOS, `fcntl(F_FULLFSYNC)` is required to ensure data reaches the storage medium. On Windows, call `FlushFileBuffers` on the temporary file, then replace with `MoveFileEx` using `MOVEFILE_REPLACE_EXISTING` and `MOVEFILE_WRITE_THROUGH`; `ReplaceFile` preserves the original file's attributes, but its `REPLACEFILE_WRITE_THROUGH` flag is documented as not supported.
- DATA-06 (metadata): Copy the original file's permissions, ownership, and extended attributes onto the temporary file before replacing. If the original is a symbolic link, write to its target. If it has multiple hard links, an atomic replace leaves the other links pointing to the old content: either replace atomically and tell the user the links will be broken, or make a backup first and then update in place. On Windows, retry briefly when the replace fails with a sharing violation, since security software, indexers, and sync clients hold files for short periods.
- DATA-05: For SQLite databases, use the Online Backup API or `VACUUM INTO` to produce a consistent copy. In WAL mode, copying only the main database file misses data that has not been checkpointed.
- INSTALL-07: Sign both the update package and the version manifest. Ship the public key with the application; keep the private key offline and plan for rotation. Refuse updates whose version is lower than the current one unless the user explicitly chooses to roll back.
- SYSTEM-12: On Windows, save quickly in `WM_QUERYENDSESSION` / `WM_ENDSESSION`; call `ShutdownBlockReasonCreate` with a reason only while a save is in progress; use `RegisterApplicationRestart` to resume after a restart for a system update. On macOS, save in `applicationShouldTerminate` and support reopening windows at login.
- COMPONENT-03: On Windows, manage child processes with a job object that has `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`; on Linux, use `prctl(PR_SET_PDEATHSIG)` together with process groups; macOS has no equivalent, so the child watches for the parent's exit. Children must not inherit unneeded handles, or the job object cannot end them.
- NETWORK-07: Use the authorization code flow with PKCE. Check that the callback's `state` matches the current request and that the redirect URI exactly matches the registered one; reject callbacks that were already used or have expired.
- PRIVACY-09: HTTP and WebSocket services bind only to the loopback address, use a random port and an access token, and validate Origin and Host. WebSocket upgrade requests usually bypass the Origin check in HTTP middleware and need their own check. Do not derive the allowed Origin from the Host header; that can be bypassed by DNS rebinding. Restrict named pipes and Unix sockets to the current user, and verify the peer process's identity on connection.
- TRUST-05: Before extracting, canonicalize each entry's target path and reject entries and symbolic links that resolve outside the target directory. Verify signatures before extracting.
- WINDOW-05, MANAGED-02: On Windows, name the single-instance mutex with the `Local\` prefix to isolate it per session; `Global\` prevents other users from launching. On macOS, `LSMultipleInstancesProhibited` affects fast user switching the same way.
- INPUT-12: On Windows, pen input goes through either Windows Ink or WinTab; when the driver or the application supports only one of them, pressure is lost (Krita's Tablet Settings and Blender's Tablet API both offer a switch). WinTab coordinates are mapped across the virtual desktop on multi-monitor setups and need correction.
- LOCALE-04: Node.js / Electron (ICU) and the JRE embed a time zone database, updated with the runtime version rather than the operating system; Python's `pytz` embeds one, and `zoneinfo` falls back to the `tzdata` package when the system has no time zone data (Windows), both updated with dependency versions. Windows updates its own time zone data through Windows Update. Prefer the system's time zone data, or update the embedded data with each release and show the data version.

**Electron / Chromium**

- INPUT-06: In `keydown` handlers, check `isComposing` (or keyCode 229) and ignore submit keys such as Enter during composition. Intercept only submit keys; returning early on every keyCode 229 also swallows Ctrl combinations and Esc.
- APPEARANCE-07: Apply `user-select: none` to non-content areas, excluding body content and information users need to copy. In production, handle the default behavior of Ctrl/Cmd + R, F5, and Ctrl/Cmd + P according to product needs. Open external links with `shell.openExternal`. Remove the default "Inspect Element" menu.
- DISPLAY-08: Set `backgroundColor` according to the current theme when creating the window, and show it with `show: false` and the `ready-to-show` event.
- SYSTEM-02: The Linux tray relies on StatusNotifierItem, which GNOME does not display by default without the AppIndicator extension. Provide an alternative entry point when no tray is available.
- SYSTEM-04: Check the return value of `globalShortcut.register`; registration fails without throwing when the shortcut is already taken.
- WINDOW-02: A custom title bar loses the Windows 11 snap layout flyout unless `titleBarOverlay` is used or hit testing is handled manually.
- TASK-08: Check the `backgroundThrottling` setting, render loops while hidden, and the resident memory of multiple renderer processes.
- NETWORK-05: `net.fetch` uses the Chromium network stack and follows the system proxy; Node.js `fetch` does not use the system proxy. Mixing the two produces inconsistent proxy behavior.
- PRIVACY-03: On Linux, the protection `safeStorage` provides depends on the secret store backend; the `basic_text` backend offers no effective protection. Use `safeStorage.getSelectedStorageBackend()` to detect the current backend.
- DISPLAY-03: Fractional scaling under Linux Wayland depends on Ozone-related launch flags and needs testing.
- INSTALL-07: On Windows, electron-updater verifies the publisher name through `verifyUpdateCodeSignature`; before 6.3.0-alpha.6 the default check could be bypassed by a tampered manifest (CVE-2024-39698). Squirrel.Mac requires the application to be signed.

**Tauri / system WebView**

- Windows depends on the WebView2 runtime (included with Windows 11; may need installation on Windows 10). Linux uses WebKitGTK; test its rendering performance, fractional scaling, and support for the Web APIs in use, for DISPLAY and TASK-07.
- The tray is part of the core (the `tray-icon` feature); global shortcuts, single instance, launch at login, and the updater are provided by plugins. Platform differences are significant; verify the SYSTEM domain item by item.
- SYSTEM-01: In Flatpak packages, register launch at login through the Background portal, with the autostart entry executing `flatpak run <app-id>` rather than the executable path inside the sandbox.
- WebView engines differ across the three platforms, as do CSS and font rendering; check APPEARANCE-03 and TYPO-01 on each platform.
- INSTALL-07: The updater plugin enforces signature verification, with the public key in `plugins.updater.pubkey`; if the private key is lost, released versions can no longer update automatically. Before updater 2.12.0 only the binary was signed, not the manifest, which allowed forced downgrades (CVE-2026-95625); upgrade and enable version signing.

**Qt**

- DISPLAY-01, DISPLAY-03: Qt 6 enables high-DPI scaling by default; set the rounding policy for fractional scale factors with `QGuiApplication::setHighDpiScaleFactorRoundingPolicy`. Wayland and X11 behave differently.
- APPEARANCE-01: Automatically following Windows dark mode requires a recent Qt 6 release; the Fusion style in older versions does not follow it.
- INPUT-06: Under Wayland, input methods depend on the text-input protocol; test fcitx5 and similar.
- DATA-06: `QSaveFile` writes to a temporary file and commits; with `setDirectWriteFallback(true)`, it overwrites the target directly when a temporary file cannot be created.
- DATA-07: `QFileSystemWatcher` stops watching a file after it is deleted or renamed; re-add the path after another program saves by replacement.

**Flutter desktop**

- A11Y-03: Standard widgets provide semantics; custom-painted or custom widgets must provide them explicitly with the `Semantics` widget.
- INPUT-06, INPUT-07: Test desktop text input and IME support thoroughly.
- INPUT-01: The native menu bar (`PlatformMenuBar`) is available only on macOS; Windows and Linux require a custom-drawn menu bar.
- The WINDOW domain depends on third-party window management plugins.

**Native frameworks (WinUI / WPF / AppKit / GTK)**

- WPF: Per-monitor DPI awareness must be declared in the application manifest.
- WinUI 3: Packaged and unpackaged distribution use different mechanisms for launch at login, file associations, and notification registration; verify INSTALL and SYSTEM separately for each distribution method.
- AppKit / SwiftUI: Sandboxed file access requires security-scoped bookmarks; for FILE-01, persist bookmarks for recent files rather than paths. Whether the application quits after the last window closes is determined by `applicationShouldTerminateAfterLastWindowClosed`.
- INSTALL-07: Sparkle is common on macOS; update archives need an EdDSA signature, with the public key in the Info.plist `SUPublicEDKey`, and DSA-only is no longer supported. WinSparkle is available on Windows; with MSIX distribution, App Installer handles updates.
- GTK: Dark mode is read through the desktop portal. Accessibility goes through AT-SPI. Support for fractional scaling under Wayland varies by GTK version.
- Linux in general: Under sandboxing, launch at login, global shortcuts, and file selection go through XDG Desktop Portal; handle backend availability, user refusal, and the final packaged identity.
