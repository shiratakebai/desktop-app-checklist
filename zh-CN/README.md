# 桌面应用能力与 QoL 清单

[English](../README.md) | 简体中文

本清单列出桌面图形应用在核心功能之外通常需要具备的能力与使用体验，供开发者在设计、实现和发布前核对。

适用于 Windows、macOS 和 Linux 桌面图形应用，与技术栈无关。本清单不是合规标准，不提供评分或认证。

## 缘起

越来越多的桌面软件主要借助 AI 编程 Agent 开发，即通常所说的 Vibe Coding。借助 Agent，许多过去需要投入大量精力的 QoL 功能，例如恢复滚动位置、处理输入法组合输入、原子保存、关闭对话框后归还焦点，一旦被提出，实现成本很低。难点不再是编写代码，而是意识到需要这项功能。

Agent 本身无法稳定地弥补这一缺口。这类功能很少被明确写出来，它们散见于问题报告、平台文档的注释和有经验的开发者的习惯中。未来模型的训练数据也无法保证覆盖它们。

本清单将这些功能集中列出，作为备忘录，供交给 Agent 或由评审者使用。

平台规范与设计系统回答的是如何正确实现已知需求，本清单回答的是哪些需求容易被遗漏。两者互为补充。

## 概览：12 项核对

以下 12 项是主清单的摘要，每项对应一到两个领域。仅针对产品承诺支持的场景核对。

- [ ] **显示与布局**：系统缩放、文字放大、主题、半屏和多显示器变化后，主要内容和操作仍可用。
- [ ] **输入与操作**：键盘、焦点、输入法、鼠标、触控板和常用编辑行为符合平台惯例。
- [ ] **辅助技术**：控件语义、关键状态和复杂内容可被辅助技术识别，核心任务可以完成。
- [ ] **上下文恢复**：返回、切换标签、重启或唤起后，回到合理的工作位置。
- [ ] **状态可见**：保存、连接、任务、权限和错误状态与实际一致；待处理事项可找到。
- [ ] **误操作恢复**：可逆操作可撤销，破坏性操作有保护，作用范围明确。
- [ ] **故障时保护数据**：保存失败、崩溃、外部修改或同步冲突时，用户的有效内容不被静默破坏。
- [ ] **数据可迁移**：用户可以找到、导出或迁移自己的数据，并知道遗漏或有损的部分。
- [ ] **与其他软件协作**：按需支持复制粘贴、拖入拖出、外部打开、在系统中定位、分享和打印。
- [ ] **设置与权限**：可发现、可调整、可复位、可重新授权；失效或降级时有反馈。
- [ ] **长时间运行**：不抢占焦点，不频繁打扰，不产生无意义的能耗；长任务和离线状态的行为完整。
- [ ] **安装、更新、故障排除与卸载**：分发渠道、数据兼容、自助恢复入口和后台退出均已考虑。

## 产品类型

一个产品可以同时属于多种类型。下表用于确定优先查看的标签和场景。

| 类型 | 示例 | 优先查看的标签 | 优先查看的场景 |
| --- | --- | --- | --- |
| **工作台** | 编辑器、IDE、笔记、设计工具 | `数据` `文本` `多窗` | S01、S04、S06、S07、S13、S21、S24、S26、S37、S39、S41、S42 |
| **按需唤起工具** | 启动器、截图、词典、剪贴板管理器 | `浮窗` `后台` | S09、S11、S19、S20、S25、S31、S33 |
| **查看与批处理工具** | 图片查看器、播放器、格式转换器、下载器 | 以无标签条目为主，按需查看 `联网`，以及 COMPONENT、MEDIA、TRANSFER 三个领域 | S02、S10、S12、S21、S22、S30、S32、S34 |

标签含义：

| 标签 | 产品是否… |
| --- | --- |
| `数据` | 持有用户创作或整理的数据 |
| `文本` | 供用户长时间阅读或编辑文字、代码、日志 |
| `后台` | 关闭窗口后仍在运行 |
| `浮窗` | 平时隐藏，通过热键唤起，用完即关闭 |
| `联网` | 依赖网络服务或账号 |
| `多窗` | 支持多窗口、多标签或多文档 |
| `分发` | 行为取决于分发方式 |

无标签的条目适用于几乎所有桌面应用。

## 使用方法

### 交给 AI 编程 Agent（推荐）

本清单主要面向借助 AI 编程 Agent 开发的项目。在待审查的项目中，向 Agent 发出以下指令：

> 将 https://github.com/shiratakebai/desktop-app-checklist 的 v1.0 标签克隆到本项目之外的临时目录，然后按照其中的 zh-CN/AUDIT.md 审查本项目。

<!-- 发布新版本时同步更新此处的标签。 -->

[AUDIT.md](AUDIT.md) 规定审查要达到的结果，具体方法由 Agent 自行决定。Agent 只在两处暂停并等待用户：审查前，确认它从代码库推断出的范围；报告完成后，由用户选择要处理的条目。报告采用固定结构，每项结论附证据。在用户做出选择之前，Agent 不修改项目。指令固定到发布标签，使审查指南停留在已审定的版本；更新的版本列在仓库的 Releases 页面。Agent 无法联网时，手动下载本仓库，并将 AUDIT.md 的本地路径提供给 Agent。

### 人工评审

1. **架构阶段**：查看 WINDOW、DATA、SETTINGS、NETWORK、INSTALL 中的基线条目。窗口模型、原子写入、配置目录和离线边界在后期修改成本最高。
2. **完善阶段**：按产品类型选出一批影响日常使用体验的条目集中检查（基线与 QoL 均可），例如输入法、剪贴板、启动闪烁、滚动位置恢复和焦点行为。
3. **发布前**：选择三到五个场景在真实设备上执行，记录哪些已实测、哪些未实测。
4. **纳入项目**：将清单复制到项目仓库，删除不适用的条目并注明原因，其余逐条处理。
