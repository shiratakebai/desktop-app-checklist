# 贡献指南

[English](../CONTRIBUTING.md) | 简体中文

## 收录标准

新条目需同时满足以下四项：

1. **用户可观察。** 描述用户获得的结果，不描述框架配置项。
2. **跨产品通用。** 多种产品都会遇到；单个产品特有的需求不收录。
3. **容易遗漏。** 清单的作用是提醒。
4. **有出处。** 指出至少一个已有产品具备该行为，或一次因缺少该行为而发生的真实失败、投诉或事故。出处写在提交说明中，不写进清单正文；来自平台方、标准组织、政府机构或软件公司的出处同时加入 [references.md](references.md)。

满足前三项但出处不足，或只适用于少数产品的内容，可提交到 [side-notes.md](side-notes.md)。

提交新条目前，先确认能否在现有条目中补充一句话来覆盖。多数"失败时如何处理""恢复后保留什么"适合作为现有条目的补充，而非新条目。

## 条目格式

```
- [ ] **ID 标题** `标签` · 基线或 QoL — 期望行为。受挫路径或衔接处的要求。\
  常见问题：一个典型缺陷。
```

- **ID**：在领域内顺序编号，已删除的编号不再使用。中英文版本使用相同的 ID。ID 是稳定的键，不是名称：checklist.md 内部的交叉引用可以只写 ID，读者就在文内，可以搜索；其他可能在没有打开清单时被阅读的地方（场景、README、AUDIT.md、审查报告），ID 后面跟条目标题。
- **标签**：仅使用七个：`数据` `文本` `后台` `浮窗` `联网` `多窗` `分发`（英文版为 `data` `text` `background` `on-demand` `network` `multi-window` `distribution`）。无标签表示适用于几乎所有桌面应用。
- **领域适用条件**：TRUST、EXTEND、AUTOMATE、LICENSE、MANAGED、FAIR、FIND、COMPONENT、MEDIA、TRANSFER 仅对部分产品有意义，适用条件写在领域标题下，不另设标签。
- **基线 / QoL**：仅用于扫读，不表示优先级。缺失会导致功能损坏、数据丢失或在部分环境中无法使用的为基线；提升效率和舒适度的为 QoL。
- **常见问题**：可选。描述一个具体、可复现的缺陷。
- **换行**：期望行为一行末尾的 `\` 使"常见问题"在渲染后另起一行。

## 写作规范

### 语体

- 使用陈述句描述期望状态，例如"写入失败时，原文件保持完好"。勾选即表示该陈述对本产品成立。
- 不使用第二人称，不使用口语、比喻、感叹和反问。
- 一段话能说清的内容不拆成多个单句段落；不添加与内容无关的回顾、定义和总结。
- 使用平台和行业通用的术语，同一概念全文用词一致。

### 不使用防御性写法

防御性写法指为预先抵御质疑而添加、却不改变读者行动的限定、澄清和免责。判断标准：删去这句话后，读者照清单做事的方式是否改变；不改变的，删去。这类写法在 AI 生成的文本中尤其常见；用 AI 修改条目时，把任务描述为"编写"或"润色"，比描述为"审核"产生的防御性写法少。

常见形式与改法：

- **弱化期望行为**，如"可能""在某些情况下""取决于具体情况"：写成确定的陈述。行为确实因产品而异时，写明由什么决定。
- **否定式边界与对比**，如"不意味着""不保证""而不是"：写成会发生的事或正确的做法。仅当误解常见且直接导致缺陷时保留"X 不是 Y"，并紧跟原因，例如"同步不是备份：错误的内容同样会被同步到所有设备。"
- **预告、自我修正与免责**，如"以下只讨论""严格来说""仅供参考"：删去，直接写内容。

范围声明（不是合规标准、不提供认证）只在文首出现一次。条目中不引用外部来源，来源列在 [references.md](references.md)。

### 内容

- **范围宽，承诺准。** 收录门槛低，表述门槛高。"提供便携模式"可以写，"所有软件必须将数据存放在程序目录"不可以。数字作为示例给出，不作为标准。
- **先写用户获得的结果，再写实现。** 条目正文写用户可观察的行为；具体 API、参数和平台实现写入附录 A，按条目 ID 索引。
- **正常路径与受挫路径一起写。** 有保存就写保存失败，有同步就写冲突，有热键就写注册失败。
- **优先覆盖衔接处。** 窗口与窗口、内存与文件、本机与其他设备、旧版本与新版本之间的衔接最容易出问题。
- **平台差异在条目内括注**，不拆分条目。
- **不建立制度。** 不增加状态模型、验收条件、评分或数据模式。需要验证时，在 scenarios.md 中增加走查场景。

## 走查场景格式

每个场景包含操作步骤、检查点和相关条目（ID 与标题）。涉及强制结束进程、断开存储、覆盖、迁移或卸载的场景使用可丢弃的样本，这一点由 scenarios.md 顶部的执行原则统一说明，各场景不再重复。场景不要求覆盖平台、设备与输入法的全部组合。

## 保持 AUDIT.md 同步

AUDIT.md 引用了 checklist.md 中定义的领域与条目 ID、条件领域，以及基线与 QoL 的划分。这些内容变化时，在同一个 Pull Request 中更新 AUDIT.md。

## 双语维护

英文版为主版本，位于仓库根目录；中文版位于 `zh-CN/`。修改条目时同步更新两种语言；只能完成一种语言时，在 Pull Request 中注明，由维护者补齐。
